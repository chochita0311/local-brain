## 터미널 열기

macOS 웹 화면의 Sessions 위에 있는 **Terminal**을 여세요.
**구성요소 설치**를 한 번 실행한 뒤 **새 터미널**을 누릅니다.
설치에는 Node.js 20 이상과 npm이 필요하며, 고정된 버전의 터미널 구성요소를
내려받습니다. 화면을 방문하는 것만으로 설치하거나 셸을 실행하지 않습니다.
데스크톱 앱에는 이 기능이 포함되지 않습니다.

**설정 → Terminal**에서 기본 작업 폴더와 셸을 저장하세요. **새 터미널**을
누르면 최신 기본값으로 새 탭을 바로 엽니다. 셸을 비우면 기본 셸을 사용하며,
직접 지정하려면 `/bin/zsh` 같은 실행 파일 경로를 입력합니다. 기존 로그인·대화형
셸 설정과 Oh My Zsh가 적용됩니다. 설정 변경은 새 터미널부터 적용하며 이미
실행 중인 작업은 유지합니다. LocalBrain은 셸 설정 파일을 수정하거나 iTerm2를
내장하지 않습니다.

한글·영문·기본 Powerline 기호용 D2Coding을 포함하며 기본 크기는13px입니다.
OS에 글꼴을 설치하거나 iTerm2 설정을 복사할 필요가 없습니다. 포함된 파일을
읽지 못하면 **글꼴 다시 불러오기**를 누르세요. 실행 중인 프로그램은 유지됩니다.
추가 Nerd Font 아이콘과 이모지는 시스템 대체 글꼴이 필요할 수 있습니다.
셸의 문자 인코딩, 글꼴의 문자 지원, 터미널의 문자 폭은 별개입니다.

## 탭과 분할

**새 터미널**은 탭을 추가합니다. 각 터미널의 **⋯** 메뉴에서 오른쪽 또는
아래쪽으로 두 개로 나눕니다. 이후 **분할 추가**로 셋·넷을 만들면2×2로
배치하며, 탭마다 최대 네 개입니다. 좁은 화면에서는
선택기로 표시할 터미널을 바꾸고 나머지는 계속 실행합니다.
**Shift+Escape**로 터미널 입력에서 메뉴로 포커스를 옮길 수 있습니다.
일반 Escape는 그대로 셸이나 실행 중인 프로그램에 전달됩니다.
분할도 입력 창 없이 바로 열며, 누른 pane의 확인된 작업 폴더와 셸을 이어받습니다.

터미널의 **×**는 해당 터미널과 관리 중인 자식 프로세스를 종료합니다.
탭의 **×**는 그 탭의 모든 터미널을 종료합니다. 실행 중인 터미널이 있으면
범위를 확인한 후 종료하며, 종료한 작업은 되돌릴 수 없습니다.

## 백그라운드에서 계속 실행하기

탭 메뉴의 **백그라운드로 보내기** 또는 **실행 중** 목록의 **백그라운드**는
실행을 유지하면서 탭만 숨깁니다. 목록의 **열기**는 같은 작업으로 돌아오고,
**터미널 종료**는 그 탭의 작업을 실제로 끝냅니다. 각 터미널의 상세 항목에서는
개별 종료도 가능합니다. 모든 탭을 숨기면 **실행 중 보기**로 이 목록을 엽니다.
**새 터미널**은 숨긴 작업의 복귀가 아니라 새 인스턴스를 생성합니다.
브라우저를 닫거나 다른 화면으로 이동해도 작업은 계속 실행합니다.

별도 로컬 서비스가 셸을 관리하므로 웹 서버를 다시 시작해도 유지됩니다.
같은 터미널을 여러 브라우저 창에서 열면 두 번째 창은 읽기 전용이며,
**제어권 가져오기**로 입력 권한을 옮깁니다. 현재 제어 중인 화면만 입력과
크기 변경이 가능합니다. 숨겨진 브라우저 페이지는 연결을 끊고 돌아오면
다시 연결합니다.

연결이 밀리면 입력을 잠시 대기시킵니다. 전송할 수 없거나 제어권을 잃으면
알림을 표시하고 미전송 입력을 취소하며, 재연결 후 자동 실행하지 않습니다.
프로그램이 터미널 응답을 읽지 않아 입력 한도를 넘으면 해당 화면에 입력 오류를
표시하고 출력을 멈춥니다. 관리에서 그 터미널을 종료하세요. 다른 터미널은 계속 사용할 수 있습니다.
붙여넣기가 일부만 전달된 경우에는 연결 후 Ctrl+C로 현재 입력을 취소하고
화면을 확인한 뒤 다시 입력하세요. 오래된 화면이면 새로고침 안내를 표시합니다.
최신 화면과 이전 관리 서비스의 복원 버전이 다르면, 작업을 마친 뒤 관리에서
서비스를 재시작하도록 안내합니다. 서비스 재시작은 해당 터미널들을 종료합니다.

화면과 배치는 용량이 제한된 서비스 메모리에 보관합니다. 재연결하면 지원하는
터미널 모드와 최근 출력을 복원하지만, 오래된 출력은 생략될 수 있습니다.
현재 엔진은 전송 중이던 제어문, 기본·대체 화면, 모드, 저장 커서, 탭 간격,
문자 속성과 링크를 새 화면에도 복원합니다. 이력을 생략해도 현재 상태가
전송 한도를 넘으면 불완전한 화면을 표시하는 대신 복원 한도를 알립니다.
이때도 관리 메뉴에서 종료할 수 있습니다. 이전 엔진은 명시적으로 갱신해야 합니다.
종료된 화면을 포함해 최대32개 터미널 기록과 화면당1000줄의 스크롤 이력을
유지합니다. 한도에 도달하면 기존 터미널을 종료·제거한 뒤 추가하세요.
서비스 중지·재시작이나 컴퓨터 재부팅 후에는 빈 상태로 시작하며 명령을
재실행하지 않습니다. 터미널 출력은 Sessions·검색·Usage에 추가되지 않습니다.
사용자 셸이나 실행한 프로그램의 자체 명령 이력·로그 설정은 그대로 적용됩니다.

## 서비스 관리

실행 중 목록의 **백그라운드 서비스**에 **시작·중지·재시작**이 있습니다.
중지는 모든 관리 대상 터미널을 종료한 다음 서비스를 중지합니다.
재시작은 같은 종료 절차를 거쳐 빈 서비스를 시작합니다.
**전체 터미널 종료**는 서비스 자체를 중지하지 않습니다. 빈 서비스는 연결과
작업이 없는 상태가 1분간 지속되면 자동으로 중지될 수 있습니다.

웹 설치를 업데이트하기 전에는 서비스를 중지하고 소스나 패키지를 갱신하세요.
의존성 구성이 바뀌었다면 구성요소를 다시 설치하세요. 웹 서버를 재시작해 변경된
서버 코드를 적용하고 브라우저를 새로고침한 뒤 서비스를 시작하거나 새 터미널을
여세요. 웹 서버만 다시 켜서는 실행 중인 관리자의 버전이 바뀌지
않습니다. 버전이 다르면 명시적으로 서비스를 중지·재시작해야 합니다.
종료 여부를 확인할 수 없으면 오류로 남기며 두 번째 관리자를 실행하지 않습니다.

서비스가 비정상 종료되면 이전 작업이 남아 있을 수 있다는 안내를 표시합니다.
이때 중지·재시작으로 이전 작업의 종료를 확인할 수는 없습니다. 해당 프로그램의
관리 방법으로 상태를 확인하고 종료하세요. 명시적으로 **새 터미널**이나 **시작**을
선택하면 과거 작업을 복구·재실행하지 않는 새 서비스를 만듭니다. 새 목록이
비었다고 이전 프로그램이 모두 종료된 것은 아닙니다. 개별 종료에 실패한
터미널은 기록과 오류를 남겨 확인·재시도할 수 있습니다.

명령줄에서도 같은 작업을 할 수 있습니다.

```sh
lb terminal service install
lb terminal list
lb terminal stop t-example
lb terminal stop --all
lb terminal service status
lb terminal service start
lb terminal service stop
lb terminal service restart
```

`list`는 터미널 목록과 ID를, `service status`는 관리 서비스 상태를 보여줍니다.
둘 다 조회만으로 서비스를 시작하지 않습니다. `stop ID`는 하나,
`stop --all`은 전체 터미널을 종료합니다. `service stop`은 관리자까지 중지합니다.
`--json`을 붙이면 기계가 읽을 수 있는 형식으로 출력합니다.
전체·서비스 종료에는 한 번의 확인이 있으며, 실행 중인 작업을 스크립트에서
종료하려면 `--yes`가 필요합니다. `--force`는 정상 종료 대기 시간을 생략하지만
관리 대상 확인을 생략하지 않습니다. 기존 `localbrain` 명령도 그대로 사용할
수 있습니다.

설치나 연결에 실패하면 해당 오류를 표시하며 Sessions와 다른 화면은 계속
사용할 수 있습니다. Node/npm 설치와 서비스 상태를 확인하세요.
관리자를 식별할 수 없으면 자동으로 강제 종료하지 않습니다. 다른 터미널과
마찬가지로, 의도적으로 분리한 프로그램도 원래 터미널의 자식임을 확인할 수 있으면 종료합니다.
원래 POSIX 세션과 자식 관계를 모두 벗어난 뒤에는 정리를 보장하지 않으며,
해당 프로그램의 관리 방법으로 종료해야 합니다.
