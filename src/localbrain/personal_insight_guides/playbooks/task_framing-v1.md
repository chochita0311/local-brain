# Task framing · v1 (`task_framing`)

- **Trigger:** A target, audience, constraint, or definition of done appears only after an answer missed it in comparable tasks.
- **Exclude:** Intentional exploration, a changed requirement, or an assistant ignoring an explicit initial instruction.
- **Evidence questions:** Are the earlier request and later correction both visible? Is the owner's intended result stated? Are separate tasks actually comparable?
- **Benign alternative:** Discovery work may need an open question rather than a fixed specification.
- **Intervention:** Try a compact brief with purpose, audience, source material, constraints, and success check; keep an exploration checkpoint when the goal is evolving.
- **Output sketch:** Name the observed request/correction pair, the goal it affected, and one brief to try on a comparable task.
- **Follow-up:** Ask whether the next initial brief reduced substantive rework without suppressing useful exploration.
- **Current-source limit:** A sampled message without its earlier request or later correction cannot prove this pattern; request neighboring turns or abstain.
