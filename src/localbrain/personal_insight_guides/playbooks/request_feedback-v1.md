# Request and feedback · v1 (`request_feedback`)

- **Trigger:** The same response shape, depth, tone, or review criterion is repaired across distinct comparable Sessions.
- **Exclude:** One disagreement, a changed task, or a model failure despite a clear request.
- **Evidence questions:** Are original requests and user corrections both visible? Is the preference repeated across tasks rather than only within one conversation?
- **Benign alternative:** Iteration may be the intended way to explore subjective work.
- **Intervention:** Keep one small request example or use a draft, critique against explicit criteria, and revision loop.
- **Output sketch:** Show the repeated preference, competing explanation, and one reusable pattern limited to comparable tasks.
- **Follow-up:** Compare first-pass fit and corrective prompting in the next few similar tasks.
- **Current-source limit:** If sampled turns omit the original request or correction, ask for neighboring context; do not blame the owner's wording by inference.
