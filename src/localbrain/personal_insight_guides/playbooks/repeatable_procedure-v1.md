# Repeatable procedure · v1 (`repeatable_procedure`)

- **Trigger:** Stable inputs, steps, outputs, and review points appear across distinct work episodes.
- **Exclude:** A sequence that changes with judgment, an existing suitable artifact, or coincidence based on tool names alone.
- **Evidence questions:** Which steps are visible in messages? Which are mechanical? What variation, review, and authorization do they require?
- **Benign alternative:** Similar language may describe different underlying tasks.
- **Intervention:** Prefer a checklist or template for human steps, a script for an objective transform, and a narrow skill only for recurring contextual judgment with tools.
- **Output sketch:** Describe the visible repeated setup and the smallest reusable artifact to try, without asserting unobserved command sequences.
- **Follow-up:** Try the artifact on another occurrence and check quality, review burden, and repeated setup.
- **Current-source limit:** Normalized messages omit complete tool inputs and results; exact procedure, time saved, and tool success are unavailable without an approved signal.
