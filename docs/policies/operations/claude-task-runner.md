# Claude Task Runner

## Purpose

The Task Runner starts a local Claude maintenance process from a Workstream for resource organization, checkpoint drafting, or priority review. LocalBrain owns the durable Run record and one linked metadata-only Maintenance Session; Claude execution must never become an ordinary indexed work Session.

## Execution Contract

- Each Run starts a new top-level Claude process rather than resuming an ordinary work Session.
- The default working directory is the user's home directory, expanded from `~`, so approved local sources can be discovered beyond an already linked project.
- The process uses `--print --output-format stream-json --verbose --permission-mode plan --json-schema`. It does not pass `--no-session-persistence`; Claude's persisted native JSONL is the Session and Usage source.
- Preparing an in-app Run creates only the `maintenance_runs` ledger row and private artifact paths. The internal header in the stdin prompt lets the next Claude-source sync classify and uniquely link the persisted primary Session as `maintenance`, `primary`, and `metadata_only`.
- The permission mode is read-only planning.
- FastAPI launches the CLI as a background child process so request handling remains non-blocking.
- The top-level agent may use subagents only when broader exploration is necessary.
- The Workstream Run form displays the selected task's base request, the exact CLI argument string generated by the same command builder used for execution, and that the base request plus optional `추가 요청` are passed through stdin. The extra text is appended rather than replacing the base request.
- Cancellation, completion, failure, and observed tool usage are persisted in `maintenance_runs`.
- Every terminal path triggers a Claude-only source sync. Native Claude message usage is normalized through the ordinary Claude producer; the Runner stream never creates a second Usage Record.
- Run state is one of `queued`, `running`, `completed`, `failed`, `cancelled`, or `interrupted`.
- The Run Console polls live status and output, exposes artifacts, and supports cancellation without blocking FastAPI requests.

`LOCALBRAIN_CLAUDE_BIN` may select the Claude executable. `LOCALBRAIN_RUN_ID` is provided to the child process for Run attribution.

## Local Retrieval First

Before Claude starts, LocalBrain performs deterministic SQLite and FTS5 retrieval without an AI call.

- The context manifest contains Session, Document, Project, local-path, and external-reference candidates.
- Session candidates are restricted to `session_class=work` and `session_role=primary`. Maintenance Sessions and subsessions never contribute candidate counts, evidence, fingerprints, manifests, or generated Suggestions, even when they already have a Workstream or Thread link. Their content is not merged into an eligible parent.
- The current Run, earlier Claude Runs, and any subagents used by those Runs remain execution activity. They must not be proposed back as new Workstream resources.
- Candidate resources and matching evidence have relevance criteria but no hard count cap.
- A resource is represented once even when it is relevant to multiple Threads.
- Many-to-many Thread assignments and evidence IDs are stored separately.
- Full evidence is written as one deduplicated file per candidate and opened only when needed.
- An unchanged candidate fingerprint carries forward the previous structured result so Claude can avoid repeated investigation. This `previous_analysis` cache is separate from candidate resources and evidence; it does not make the previous Run or its subagents retrieval inputs.

Claude should use external MCP tools only to fill gaps that remain after local evidence review.

## MCP Budget

`LOCALBRAIN_MCP_CALL_BUDGET` sets the advisory MCP call budget for one Run and defaults to `20`.

The current Claude CLI can cap monetary spend but does not expose a hard MCP call-count limit. LocalBrain therefore:

- states the budget in the prompt
- records observed `mcp__*` stream events
- reports budget overruns after calls occur

This is a soft policy, not strict enforcement. A future MCP proxy or broker boundary is required for a hard call-count limit.

## Persistence

Run metadata is stored in `maintenance_runs`; the native Claude Session and its Usage Records are normalized into `sessions` and `usage_records` inside `localbrain.db`. Artifacts are stored under:

```text
~/Library/Application Support/LocalBrain/runs/<run-id>/
```

Artifacts include the generated prompt, manifest and fingerprints, operational stream output, structured result, and per-resource evidence. The stream drives the Run Console and result parsing but is not a Session or Usage rebuild source. Native Claude JSONL remains authoritative. Artifacts are private runtime data and must remain outside Git.

## Review And Mutation Rules

- Structured Resource and Checkpoint candidates are saved as pending Suggestions.
- A Resource candidate targets the most relevant Thread by default.
- A Workstream-level target is reserved for evidence genuinely shared by multiple Threads.
- Accepting a Resource materializes its local path or external reference and then creates the link.
- Accepting a Checkpoint creates a versioned confirmed state with the current resource snapshot.
- Rejected Suggestions remain visible and can be restored.
- Refresh replaces eligible pending Claude Run Suggestions only after a new structured result succeeds.
- Accepted and rejected decisions survive refresh.
- A failed or cancelled Run must not clear the review queue or silently mutate Workstream organization.

Only explicit user acceptance may change Workstream organization.

## Index Exclusion

Maintenance prompt headers identify housekeeping activity:

```text
[LOCALBRAIN_RUN: lb-<12 hex characters>]
[MODE: maintenance]
```

Sessions beginning with this exact internal header retain source metadata but are excluded from activity events, full-text search, workflow statistics, and the Sessions Dashboard primary-work Session denominator. A registered Run ID populates the unique Run FK; an unregistered header remains maintenance with no physical Run relation. Claude child Sessions inherit maintenance classification and metadata-only indexing from a linked maintenance parent while retaining their own directly observed Usage Records; only the primary holds the unique Run FK. Direct Maintenance Usage Records remain eligible for token and estimated-cost totals. Run artifacts remain outside ordinary Session and Local Context ingestion.
