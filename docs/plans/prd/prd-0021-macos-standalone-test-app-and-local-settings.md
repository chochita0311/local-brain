## Public Distribution Goal — 2026-10-20

제품의 목표는 **일반 Mac 사용자가 내려받아 설치·실행하는, 회사와 무관한 공개 앱**이다.
내부 Drive와 팀원 테스트는 초기 확인 수단으로 선택했던 경로다. 회사 계정·내부망·회사
인증서·개발자의 개인 경로를 제품 사용의 전제 조건으로 삼지 않는다. 공개 배포라는
요구만으로 소스 코드의 공개나 라이선스 선택까지 확정하지 않는다.

공개 배포본은 지원하는 Mac의 기본 보안 설정에서 개발자 확인 실패로 차단되지 않아야
한다. 사용자에게 인증서 설치, `Open Anyway`, 격리 속성 제거 명령이나 보안 기능
비활성화를 정상 설치 절차로 요구하지 않는다. macOS의 표준 다운로드 앱 열기 확인과
사용자가 선택한 자료에 대한 접근 권한 요청은 유지한다. 모든 설정·DB·세션·문서와
개인 캐시의 로컬 보존 원칙, 사용자별 소스 등록, 모델 없는 기본 사용도 유지한다.

App Store 외부에서 이 기준으로 배포하려면 배포 주체의 Apple Developer ID 서명,
동봉 실행 요소의 배포 요건, Apple 공증과 티켓 첨부를 준비하고 다운로드한 배포물로
첫 실행을 검증해야 한다. `.app` + ZIP 형태를 유지할 수 있으며 App Store 등록이나
DMG 제작을 필수로 추가하지 않는다. 공증 제출물에는 프로그램만 포함하고 사용자
자료를 포함하지 않는다. 모델 다운로드의 HTTPS 검증은 유지하며 macOS의 표준 신뢰
저장소 사용을 특정 회사 인증서 설치 요구로 해석하지 않는다.

현재 전달본은 **ad-hoc 서명·미공증 테스트 앱**이다. 기존 앱별 실행 허용 안내는 이
테스트본의 한계이며 공개 배포의 완료 기준이 아니다. 아래 테스트 단계의 계약·실행
기록은 그대로 보존한다. 공개 배포 준비는 별도 Feature·검증 범위를 구체화해야 하며,
실제 가입·결제·서명 자격 증명 사용·Apple 업로드·공개 게시를 수행한 상태가 아니다.
이번 목표 확인은 그러한 외부 행위의 실행 승인으로 간주하지 않는다.

## Request Summary

개발자의 기존 로컬 환경에서 실행하던 LocalBrain을 다른 사용자도 자신의 Mac에서 빠르게 시험할 수 있는 **독립 실행 테스트 앱**으로 만든다. 전달 형태는 `LocalBrain.app` 하나를 담은 ZIP을 기준안으로 삼고, 압축을 푼 앱을 더블클릭해 실행한다. 별도 설치 프로그램·Applications 복사·App Store 등록을 필수 절차로 만들지 않는다. 사용자별 세션·문서 경로와 일반 설정은 로컬에 저장하고, 하단 설정 진입점과 분류형 설정 대화상자, 첫 실행 안내, 선택형 검색 모델 설치를 제공한다.

첫 제품의 중심은 **세션 탐색·상세, 세션 대시보드, Local Context**다. 모델을 설치하지 않아도 기본 검색을 사용할 수 있어야 한다. 사용자는 전체 작업의 Feature·커밋 규모를 먼저 알고 싶어 하며, 최초 요청은 이를 PRD로 문서화하는 단계였으며, 이후 사용자가 현재 범위 전체 구현과 관련 테스트·브라우저·앱 실행 검증을 승인했다.

`2026-10-18` 후속 요청은 다른 Mac 사용자도 독립 앱처럼 설치·실행하고, 모든 설정·사용자 데이터를 로컬에 보관하며, 보안과 공통 설정 레이어를 갖추기 위해 남은 결정을 정리하는 일이다. 최상위 `Dashboard`, `Workstreams`, `자동 작업`, `Atlassian`, 세션 상세의 `작업 흐름`은 설치형에서 제외한다. 기존 세 영역과 현재 메뉴 구분에 따라 `Sessions Dashboard`는 유지한다.

같은 날 후속 선택에서 Tauri·Apple Silicon을 채택하고 Insights도 숨기기로 했다. 모델 없는 검색은 기존 deprecated 키워드 검색을 재사용한다. 경로 일반화는 에이전트 프로필·세션 저장소, Git 프로젝트, 문서 위치를 각각 다룬다. 네트워크·에이전트 통신은 현재 허용된 사용 수준을 유지하고, 별도 네트워크 통제 제품이나 앱 자체 암호화 기능은 첫 범위에 추가하지 않는다.

이후 사용자는 정식 배포 준비보다 **다른 사용자에게 단일 실행파일 같은 형태로 빠르게 전달해 테스트하는 목적**임을 명확히 했다. Developer ID 가입·공증·DMG 제작은 현재 선행 조건에서 제외한다. Tauri·Apple Silicon과 기존 제품 범위는 유지한다. 아래의 “설치형”은 개발 checkout과 분리된 앱의 기능 구분을 뜻하며 설치 마법사나 유료 서명 배포를 요구하는 표현으로 사용하지 않는다.

테스트 전달 채널은 **내부 Drive**로 선택했다. 로컬에서 패키징한 앱을 확인한 뒤 프로그램 ZIP을 공유하고, 팀원이 내려받아 각자의 Mac에서 실행하며 자신의 세션·문서 경로를 등록한다. 개발자 Mac의 성공은 첫 확인이며, 다른 Mac에서의 실행 가능 여부는 같은 ZIP의 다운로드·압축 해제·실행 결과로 확인한다. Drive는 프로그램 전달용이고 설정·DB·원문·개인 캐시의 공유 또는 동기화 저장소가 아니다.

후속 요청은 세션 목록의 수동 동기화에 의존하지 않고 너무 잦지 않은 주기로 세션을 가져오는 것이다. 사용자는 기본 10분 간격과 보조 `지금 동기화`를 선택했고, **현재의 로컬 브라우저 실행과 배포 앱에 공통으로 계속 적용하는 기능**임을 확인했다. 공통 백엔드가 실행 중일 때 동기화하고 주기 설정은 로컬에 저장해 재시작 후에도 유지한다. 등록한 로컬 세션의 자동 갱신을 제품 범위에 추가하며, 제외된 `자동 작업` 제품을 다시 포함하는 결정으로 해석하지 않는다.

### Human Direction

- 개인 개발 환경을 넘어 다른 사용자가 설치하고 실행하는 macOS 앱을 원한다.
- 실행 가능한 앱을 하나의 배포물로 전달하고, 포터블하게 사용할 수 있기를 원했다. 후속 검토에서 우선 설치에 집중하고 세부 데이터·설정 이동은 기록한 뒤 나중에 다루기로 선택했다(OP-03).
- 사이드바 하단 톱니바퀴로 설정을 열고, ChatGPT 설정과 비슷하게 분류와 내용을 함께 보여주는 구성을 원한다. 정확한 화면 복제나 제공된 시각 시안은 없다.
- 첫 실행에 필요한 설정을 안내하고, 모델 설치는 선택으로 둔다. 사용자가 처음 표현한 “LIKE 검색”은 후속 선택에서 기존 deprecated 키워드 검색 동작을 가리키는 것으로 확정했다(OP-08).
- 같은 도구라도 사용자가 여러 세션 경로를 등록할 수 있어야 하며, 세션 목록과 대시보드에서 각각을 선택할 수 있어야 한다.
- 지금까지 개인 환경을 전제로 했던 값을 공통화하고, 사용자 설정은 해당 사용자의 로컬에 저장한다.
- 자동 작업·Workstreams·Dashboard는 계속 개발 중인 영역이다. `2026-10-18` 사용자는 이들과 Atlassian, 세션 상세의 `작업 흐름`을 설치형에서 명시적으로 제외했다. 이전 Atlassian 포함 여부의 불확실성은 이 결정으로 해소되었다.
- 후속 요청은 “전체적으로 몇 개의 커밋과 Feature로 작성할지 제시하고, 우선 PRD 문서를 만들기”다.
- 후속 OP-09 검토에서 시작 화면·시간대·프로젝트 표시, 저장 위치·용량 확인, 백업·복원·캐시 정리를 첫 제공 범위로 선택했다. OP-03의 이동 보류와 구분해 백업·복원은 기존 기준안의 같은 Mac 복구 범위로 둔다.
- 일반 설정 파일과 기존 저장소의 역할, 환경변수 적용, 기존 설정 보존, 적용 시점은 처음에는 상세 설명 요청이었다. `2026-10-18` 후속 선택에서 OP-09의 추천 방향을 채택했으며, 필드별 계약은 C01에서 상세화한다.
- `2026-10-18`: 모든 설정·데이터의 로컬 저장, 보안 중시, 공통 설정 레이어, 특정 개인의 Mac 경로·환경에 의존하지 않는 설치와 독립 앱 사용 경험을 요구했다. 개발 중인 별도 기능의 구현·기록은 설치형 포함 여부와 구분한다.
- 같은 날 OP-01은 Tauri, OP-02는 Apple Silicon, OP-04는 Insights 숨김으로 선택했다. OP-05·06·09·12는 제시한 추천 방향을 채택했다.

- OP-11·13의 추가 보안 범위는 과하다고 정정했다. 현재 허용된 네트워크·에이전트 통신과 로컬 자료 보존 수준을 유지하며, 새 통신 허용 목록 체계·앱 DB/백업 암호화·앱 잠금은 추가하지 않는다.
- OP-10은 Developer ID 등 배포 준비에 대한 설명 요청이다. 개발자 프로그램 가입·결제·인증서 생성/사용·외부 공개 승인은 아니다.
- OP-10 후속 정정: 현재는 다른 사용자와 빠르게 시험하는 단계이며 단일 실행파일 같은 전달 경험을 원한다. 정식 서명 배포의 준비를 현재 테스트의 필수 조건으로 삼지 않는다. `.app` + ZIP 전달과 유료 인증서 없는 ad-hoc 서명은 이를 위한 구현 기준안이다.
- OP-10 전달 채널 선택: 사용자는 로컬 실행 확인 후 내부 Drive로 앱 파일을 공유하고 팀원이 받아 사용해보는 흐름을 원한다. 이 선택은 전달 설계이며 현재 파일 업로드나 팀원 통지를 수행하라는 요청은 아니다.
- 주기 동기화 추가: 사용자는 끝까지 진행 가능한지 확인하면서, 배포 앱은 세션 목록의 수동 동기화 대신 너무 잦지 않은 주기로 동기화해야 한다고 요구했다. 후속 질문에서 앱 실행 중 기본 10분 간격과 보조 `지금 동기화` 유지를 선택했다. 완료 후 간격 계산·설정 선택지·중복 및 복귀 처리는 아래 설계 기준안이며, 전체 PRD나 구현 승인과는 구분한다.
- 주기 동기화의 공통 적용 확인: 사용자는 현재 로컬에서 브라우저로 실행할 때도 영구 반영되는 기능인지 확인했다. C13은 공통 백엔드 기능으로 두어 로컬 웹 실행과 배포 앱 모두에 적용하고, 로컬 주기 설정을 재시작 후에도 유지한다. 서버를 종료한 동안의 실행까지 요구하는 것은 아니다. 앞선 `지금 동기화` 표현은 기존 Sessions의 `동기화` 버튼 역할을 가리킨다.
- `2026-10-19` 개인화 검토: 사용자는 여러 Mac 사용자가 각자의 폴더 구성과 취향에 맞게 사용할 수 있는 일반화 방향을 정리하자고 요청했다. 이어 현재 사용자의 macOS 홈을 `~`로 줄이고 그 아래 경로를 그대로 표시하는 방식을 제안했다. 아래 후속 설계안은 이를 반영하며 앱 변경 완료를 뜻하지 않는다. 후속 정정에서는 표시 선택 자체와 기준 위치 개념을 제거하고 홈 축약을 고정 규칙으로 삼도록 요청했다. 이 정정은 C07의 기존 표시 설정·별칭 제안을 대체한다.

`2026-10-18` 보안 검토에서 다음 공식 자료를 추가 확인했다. 이는 설계 근거이며 LocalBrain의 보안 검증 결과가 아니다.

- 후속 사용자 결정으로 별도 DB·백업 암호화와 추가 네트워크 통제는 첫 범위에서 제외했다. 위 자료를 새로운 보안 제품 요구나 현재 구현의 인증으로 확대하지 않는다.

- [Apple Developer Program 등록](https://developer.apple.com/programs/enroll/): 개인 가입이 가능하며 이중 인증된 Apple Account가 필요하다. 연회비는 99 USD이고 지역별 결제 금액은 가입 과정에서 확인한다.
- [Tauri macOS signing](https://v2.tauri.app/distribute/sign/macos/): 개발자 신원을 인증하는 App Store 외부 배포용 인증서는 `Developer ID Application`이며 Mac Keychain의 서명 정보를 Tauri 빌드에 연결할 수 있다. 무료 개발 계정은 공증을 지원하지 않는다. 아래 테스트 전달은 이 방식과 구분한 ad-hoc 서명을 사용한다.
- [Apple Developer ID](https://developer.apple.com/developer-id/): 서명과 hardened runtime, 공증 서비스의 검사와 티켓 발급·첨부를 설명한다. 공증은 배포 프로그램을 Apple에 제출하는 절차이며 사용자 설정·DB 제출을 뜻하지 않는다.

후속 테스트 배포 정정에서는 [Tauri app bundle](https://v2.tauri.app/distribute/macos-application-bundle/), [ad-hoc signing](https://v2.tauri.app/distribute/sign/macos/#ad-hoc-signing), [Apple의 미공증 앱 실행 안내](https://support.apple.com/en-us/102445)를 확인했다. `.app`은 실행 파일·리소스·라이브러리를 담은 디렉터리 번들이며, ad-hoc 서명에는 Apple이 인증한 개발자 신원이 필요하지 않다. 다만 다운로드한 앱에 대한 macOS 첫 실행 허용 요구는 남을 수 있다. 유료 가입·Developer ID·공증 안내는 이후 배포 검토용 정보로만 보존한다.

## Product Intent

사용자는 앱을 열고 자신이 가진 세션 기록과 문서 위치를 선택한 뒤, 모델 없이도 탐색·읽기·사용량 확인·기본 검색을 시작할 수 있다. 의미 기반 검색이 필요할 때 공개 모델을 명시적으로 설치하며, 준비 과정이나 실패가 기본 기능 전체를 막지 않는다.

앱 교체·업데이트, 설정 변경, 모델 추가가 사용자 자료를 개발자의 경로나 환경에 종속시키지 않아야 한다. 프로그램은 하나의 `.app`으로 전달하고 사용자 설정·DB·원본·캐시는 각 로컬 소유와 복구 방법을 유지한다. 실행 프로그램을 쉽게 옮겨 받는 것과 모든 사용자 데이터를 앱 안에 넣어 이동하는 것은 구분한다. 후자는 기존 OP-03의 후속 범위다.

| 세션 동기화 | 확인한 Session 진입점은 수동 실행이며, 현재 버튼은 완료 뒤 페이지를 다시 불러온다. 수집기는 파일 크기·수정 시각·처리 계약과 파생 근거가 유효하면 재처리를 생략하지만 파일 후보 탐색은 수행한다. 각 스트림 요청은 별도 작업을 시작하며 버튼의 중복 방지는 해당 화면에 한정된다. | 주기 실행·수동 실행을 묶는 공통 실행 소유와 중복 방지, 비용 관리, 화면 상태를 보존하는 갱신이 필요하다. 주기마다 전체 재수집을 강제하지 않는다. |
| 검색 갱신 | 기존 검색 서비스는 5초 간격으로 DB/WAL 변경 등을 확인한다. 이는 원본 세션을 수집하는 주기가 아니며 소스 상태 기록도 DB 변경 감지에 영향을 줄 수 있다. | 10분 세션 동기화와 검색 인덱스 준비를 구분한다. 변경 없는 수집의 상태 기록만으로 전체 임베딩을 반복하지 않도록 기존 재사용·갱신 계약과 실제 비용을 확인한다. |
| 원본 생명주기 | 접근 불가·설정 오류·실패한 스캔은 기존 데이터를 보존한다. 동일한 읽기 가능한 root의 정상 스캔은 사라진 원본의 정규화된 기록을 정리할 수 있다. | 기존 인덱스를 영구 원본 보관소라고 약속하지 않는다. 새로운 영구 보존 정책은 별도 범위다. |
| 검색 | 공유 헤더는 `/natural-search`로 연결된다. `/search`의 FTS5는 남아 있으나 일반 탐색·복구 경로에서 제외하는 승인된 계약이 있다. | 모델 없는 기본 검색 제공은 현재 진입점 계약의 명시적 변경이다. 기존 자연어 검색 내부의 어휘 경로만으로 모델 독립 실행이 보장되지 않는다. |
| 모델 | Qwen3-Embedding-0.6B 가중치는 약 1.21GB이며 실행 라이브러리와 인덱스는 별도다. 4B·8B 생성 모델은 실험 기능이다. | 다운로드, 파일 검증, 실행 환경 준비, 자료 인덱싱, 사용 가능 상태를 구분한다. 모델 실행 근거는 현재 Apple Silicon에 한정되고 Intel은 의존성 해석만 확인되었다. |

| Insights | 로컬 스킬 사용·참조 통계와 Codex CLI를 통한 외부 모델 분석 실행이 함께 있다. | 사용자 선택에 따라 설치형에서는 Insights 전체 진입·분석 실행을 숨긴다. 기존 보고서·집계 데이터는 보존하며 일반 사용량 대시보드는 유지한다. |

## Confirmed Scope

여기서 confirmed는 사용자 요청에서 확인한 제품 요구다. 현재 전체 범위는 구현 승인되었으며 실제 완료 여부는 Feature/Run의 검증 근거로 판단한다.

1. **Tauri 기반 Apple Silicon macOS 앱:** 동봉 Python/FastAPI와 기존 화면을 활용하며, 개인 개발 checkout이나 개인 경로를 필수 입력으로 요구하지 않는다. 최소 OS·실제 지원 사양은 번들 실행 근거로 정한다.
2. **세 영역 중심의 첫 제품:** 세션 탐색·상세, 세션 대시보드, Local Context를 다듬는다. 세션 목록은 상세로 들어가는 탐색면이며 별도의 네 번째 제품 영역이 아니다.
3. **로컬 설정과 공통화:** 사용자별 경로·선택을 로컬에 저장하고 UI에서 관리한다. 개발자 전용 기본값과 현재 사용자의 설정을 구분한다.
4. **하단 설정 진입과 분류형 화면:** 사이드바 하단에서 설정을 열고 분류와 값을 함께 확인할 수 있다.
5. **첫 실행 안내:** 필요한 소스·경로와 선택 기능을 설명하고 나중에 설정을 바꿀 수 있다.
6. **모델 없는 기본 사용:** 세션·문서 열람, 대시보드와 기본 검색을 모델 설치 완료에 종속시키지 않는다. 기본 검색은 deprecated `/search`의 기존 키워드 검색 동작을 재사용하되 설치형 자료 범위를 적용한다.
7. **선택형 로컬 검색 모델:** 설치 여부를 사용자가 결정하고, 설치·준비·오류 상태를 확인할 수 있다.
8. **여러 세션 경로:** 같은 도구의 여러 경로를 별도 소스로 등록하고 목록과 대시보드의 소스 선택에 일관되게 반영한다.
9. **단일 앱 전달과 테스트:** Python·검색 실행 라이브러리를 `.app`에 동봉하고 공개 모델 가중치만 선택 다운로드한다. 일반 사용자에게 수동 서버 명령·별도 runtime 설치·설치 마법사를 요구하지 않는다. ZIP 해제 후 앱 실행을 기준안으로 하며 Developer ID·공증은 첫 테스트의 선행 조건이 아니다.
10. **설치 우선과 이동 후속:** 첫 제공은 설치에 집중한다. 세부 데이터·설정을 다른 위치나 Mac으로 옮기는 기능은 [후속 항목](#deferred-data-and-settings-transfer)으로 기록한다. 기존 위치의 설정을 호환되게 읽는 일은 계속 필요하다.
11. **일반 설정과 데이터 관리 항목:** 시작 화면·시간대, 고정 홈 축약 경로 표시, 저장 위치·용량 확인, 같은 Mac의 수동 백업·복원·캐시 정리를 포함한다. 일반 설정 TOML과 기존 도메인 저장소를 유지한다. 일반 설정은 파일에 저장된 값을 따르고 없는 항목만 기본값을 사용하며 환경변수로 덮어쓰지 않는다. 시작 화면은 다음 실행, 시간대는 저장 후 갱신하며 과거 Usage 귀속은 보존한다. 필드와 복구 상세는 해당 Feature에서 고정한다.
12. **설치형 제외 기능:** 최상위 Dashboard와 그 개발 중 학습 화면, Workstreams, 자동 작업, Atlassian, Insights 전체, 세션 상세 작업 흐름을 설치형에서 제공하지 않는다. Sessions Dashboard는 세션 사용량 영역으로 유지한다. 개발판 코드·보존 데이터 삭제를 요구하는 결정은 아니다.
13. **로컬 저장과 현재 통신 수준:** 설정·DB·인덱스·보존 기록·진단·백업은 로컬에서 관리한다. 현재 허용된 네트워크·에이전트 통신은 유지하고 별도 허용 목록 관리·앱 DB/백업 암호화·앱 잠금은 추가하지 않는다. 로컬 저장과 명시적으로 허용된 통신을 구분하며, 새 자동 자료 업로드나 클라우드 계정을 기본 사용 요건으로 만들지 않는다.
14. **공통 설정 레이어와 경로 일반화:** 에이전트 홈/세션 경로와 문서 위치를 구분하고 여러 사용자 지정 경로를 관리한다. Git 작업 경로는 세션의 근거를 유지하고 홈 축약은 등록 없이 적용한다. 읽기·검증·저장·적용은 공통 레이어를 사용하되 값별 정본은 하나다. 개발자의 특정 경로·회사 프로필·CLI 인증 상태를 필수 의존성으로 삼지 않는다.
15. **Context와 Mac 사용 방식:** 폴더·텍스트/Markdown, 기존 추출 범위의 PDF, 명시적 권한을 받는 선택형 Apple Notes를 제공한다. 단일 인스턴스·Dock 창 복원·`⌘,` 설정, 창 닫기와 `⌘Q` 완전 종료를 구분하는 추천을 채택했다.
16. **주기적 세션 동기화:** 로컬 브라우저 실행과 배포 앱이 공통 백엔드의 기본 10분 동기화를 사용한다. 백엔드가 실행 중일 때 등록한 로컬 세션을 가져오며 주기 설정은 로컬에 저장해 재시작 후에도 유지한다. 필요하면 기존 Sessions의 `동기화` 버튼을 사용한다. 버튼을 누르는 것이 최신 기록을 가져오는 필수 절차가 되어서는 안 된다. 완료 후 간격 계산·중복 실행·잠자기 복귀·설정 변경·화면 상태 보존은 [동기화 기준안](#periodic-session-synchronization)에서 구체화한다.

## Proposed First-Release Boundary

아래는 승인된 범위와 후속 정정을 반영한 **13개 Feature·21커밋 산정 기준안**이다. 21개는 초기 예상치이며 실제 Git 커밋 수를 뜻하지 않는다. 테스트 전달 방식의 기준안과 기술 근거는 [Uncertainty](#uncertainty)에서 구분한다.

## Excluded Scope

- 사용자 요청에서 설치형 밖으로 둔 최상위 Dashboard·학습·Workstreams·자동 작업·세션 작업 흐름의 화면과 실행 기능. 개발판 작업의 계속 여부와 기존 승인 상태는 각 소유 문서에서 관리한다.
- 사용자 결정으로 제외한 Atlassian의 탐색·등록·연결·동기화·인증·외부 실행 기능. 기존 근거·원문 URL·DB를 지우는 작업으로 확대하지 않는다.
- Insights 화면·진입·새 분석 실행·별도 보고서 열람 UI. 기존 보고서와 집계 기록은 로컬에 보존한다.
- 새 네트워크 허용 목록 관리 체계, 앱 DB·백업 암호화, 앱 잠금과 별도 보안 관리 UI. 기존 로컬 권한·원본 보호·허용된 통신 규칙은 유지한다.
- 첫 테스트를 위한 Apple Developer Program 가입, Developer ID 발급·공증 업로드, DMG/설치 마법사, App Store 등록과 자동 업데이트 체계. 일반 배포가 필요해질 때 다시 검토한다.
- 클라우드 동기화, 팀 계정, 여러 사용자 서비스, 원격 데이터 업로드를 기본 전제로 만드는 일.
- 모델 필수 설치, 앱 실행·설정 열람만으로 시작하는 다운로드·외부 추론, 개인 자료를 배포물에 포함하는 일.
- 검색 모델 교체, 재학습, 비교용 reranker나 실험용 4B·8B 생성 모델의 일반 사용자 관리 화면.
- 기존 화면을 새 프런트엔드 프레임워크로 전면 재작성하거나 SQLite 데이터 모델 전체를 교체하는 일.
- 사용자 선택에 따라 첫 제공에서 세부 데이터·설정을 다른 위치나 Mac으로 옮기는 기능. [후속 항목](#deferred-data-and-settings-transfer)에 보존한다.
- 사용자 동작 없는 모델 다운로드, 유료 인증서 사용, 실제 Drive 업로드·팀원 통지·Git push·릴리스 발행. 현재 구현 승인은 이 외부 전달 행위의 승인을 뜻하지 않는다.

Intel은 Apple Silicon 우선 선택에 따라 첫 범위에서 제외한다. 다른 OS, 자동 updater, 소스별 수집 일시정지, 전체 초기화 등의 제외는 위 **제안 기준안**에 속한다. 로컬 웹·배포 앱 공통의 주기적 세션 동기화 설정은 이번 범위이며 cron·상시 파일 감시·백엔드 종료 후 상주 수집기는 포함하지 않는다. 데이터·설정 이동은 사용자가 첫 제공 뒤로 미룬 항목이다. 어느 쪽도 영구적인 제품 비목표로 취급하지 않는다.

### Deferred Data And Settings Transfer

`2026-10-16` 사용자 결정에 따라 설치 이후의 데이터·설정 이동은 후속으로 기록한다. 다른 Mac·사용자 계정으로 옮기기, 같은 Mac에서 앱 데이터 저장소를 다른 폴더·디스크로 옮기기, 원본 경로 치환, 모델 포함 이동 패키지는 이후 필요에 따라 범위를 정할 검토 대상이다. 지금 구현하거나 완료로 처리하지 않는다.

현재 범위의 백업·복원은 같은 Mac에서 앱 소유 상태를 복구하는 목적이며, 대상 위치가 바뀌는 이동 기능은 약속하지 않는다. 기존 위치의 설정 형식 호환 처리(C01), 등록한 원본 위치의 명시적 재연결(C02), 앱 교체 시 사용자 데이터 보존은 각각의 범위를 유지한다. 이들은 원본 파일이나 전체 앱 데이터의 물리적 이동을 수행하는 기능이 아니다.

## Installed Product And Security Boundary

아래는 로컬 저장·일반화와 일반적인 로컬 앱 보호 범위를 정리한 것이다. 후속 사용자 결정에 따라 OP-11·13에서 제안했던 추가 통신 제한·암호화 제품 범위는 제외했다. 설치형이 기존 로컬 경계를 유지하는지 확인하는 일은 필요하며, 이 문서가 현재 구현의 안전성을 인증하지 않는다.

### Product Availability And Settings Ownership

- 설치형이 제공하는 기능의 허용 목록과 사용자 설정을 구분한다. 설치형에서 제외한 화면·API·작업 실행·재시작 복구가 사용자 설정 파일 변경이나 직접 URL 접근으로 활성화되어서는 안 된다. 기존 개발판의 승인된 기능과 데이터는 보존한다.
- 세 영역과 설정을 하나의 탐색 흐름으로 제공한다. Sources의 사용자용 관리는 설정에 통합하고 Schema는 개발판에 둔다. 실행할 수 없는 기능으로 향하는 버튼·내부 링크를 남기지 않는다. 일반 원문 URL은 보존하되 방문은 사용자 행동으로 한정한다.
- 설정 UI·CLI·데스크톱 실행부는 값별 정본과 공통 검증·저장·적용 규칙을 공유한다. 일반 설정 TOML·세션 TOML·검색 JSON·Context DB의 역할을 유지하고 동일 항목을 두 곳에서 독립 수정하지 않는다. 일반 설정은 로컬 파일의 값과 없는 항목의 기본값으로 결정하며, 화면 저장값을 환경변수로 덮어쓰지 않는다. 필드별 검증·호환·동시 변경·적용 알림 계약은 C01에서 잠근다.
- 사용자별 home·명시적 소스 등록을 사용한다. 회사용 소스·프로필을 자동 선택하지 않고, 소스 이름·provider·고유 ID·경로를 구분한다. 목록·상세·Chart·대시보드의 필터와 표시가 같은 등록 정보를 사용해야 한다. 기존 사용자의 고유 ID·경로와 고정된 Usage 귀속은 보존한다.
- 첫 설치는 후보 경로 제안과 등록 동의를 구분하고, 빈 소스·다수 소스·숨김 폴더·외장 볼륨의 일시 부재·읽기 권한 거부를 처리한다. 일반 사용에 개발 checkout, 터미널, 사용자가 별도로 설치한 Python/uv/Homebrew, Codex·Claude CLI 로그인이나 회사 gateway를 요구하지 않는다.

### Local Storage And Existing Communication

1. **로컬 보존:** 설정·DB·개인 인덱스·보고서·진단·백업을 로컬에서 관리하고 클라우드 동기화나 자동 원문 업로드를 추가하지 않는다. OS나 사용자가 별도로 구성한 파일 동기화를 앱이 차단하는 범위는 아니다.
2. **현재 허용된 통신 유지:** 공개 자산 다운로드, 사용자가 여는 링크, 기존에 허용된 네트워크·에이전트 통신은 기존 권한과 목적 안에서 사용할 수 있다. 앱 전용 네트워크 허용 목록·차단 관리 UI·매번 추가 승인 절차를 신설하지 않는다. 이 결정이 개인 자료의 무차별 전송 권한이나 설치형에서 제외한 Insights·Atlassian·자동 작업의 재활성화를 뜻하지는 않는다. 로컬 검색의 원격 fallback은 추가하지 않는다.
3. **로컬 앱의 기본 보호:** 백엔드는 로컬 통신 범위를 유지하고, 앱 창·백엔드·자식 프로세스의 시작과 종료를 함께 관리한다. 앱 내부 접근 보호와 WebView 권한은 C04에서 필요한 범위로 정한다. 가져온 문서는 기존 안전한 렌더링을 유지하고 원문 속 코드·명령을 자동 실행하지 않는다. 별도 계정 시스템이나 강제 App Sandbox 도입을 첫 제품 요구로 추가하지 않는다.
4. **원본·권한·자격 정보:** 선택한 소스만 읽고 원본 파일·에이전트 설정·인증 파일을 수정하거나 앱 설정으로 복제하지 않는다. 필요한 파일/Notes 권한은 해당 기능 선택 시 요청하며 거부·철회는 해당 소스에만 영향을 준다. 기존 사용자별 파일 권한과 OS 또는 기존 에이전트의 자격 정보 보관 방식을 유지한다. 관리자 권한·전체 디스크 접근을 기본 설치 조건으로 삼지 않는다.
5. **복구와 테스트 전달:** 설정 저장·백업·복원 실패가 기존 상태를 지우지 않도록 하고 기존 최소 진단·로그 원칙을 유지한다. 앱 자체 DB 암호화·암호화 백업·앱 잠금은 첫 범위 밖이다. 전달본은 공통 코드·검토한 자산·실행 의존성만 포함하며 개인 자료·설정·인증정보를 포함하지 않는다. 기존 모델 무결성 확인과 의존성 재배포 조건·ad-hoc 서명·첫 실행 제약은 C09/C12가 확인한다. Developer ID·공증은 후속이다.

### User-Owned Path Categories

“경로”를 하나의 전역 root로 합치지 않는다. 다음은 OP-07의 일반화 요구를 나눈 설계 방향이며, 정확한 필드와 재연결 판정은 C01/C02에서 고정한다.

| 구분 | 사용자가 지정하는 값과 사용 목적 | 설정 소유와 제한 |
| --- | --- | --- |
| 에이전트 홈·프로필과 세션 저장소 | 같은 Codex/Claude라도 이름과 위치를 여러 개 등록한다. 홈을 선택하면 provider별 세션 하위 위치를 제안하고 실제 읽을 위치를 보여주며, 사용자 지정 세션 위치도 받는다. | 세션 소스 설정이 고유 ID·provider·이름·경로 관계를 소유한다. 현재 TOML의 root는 세션 저장소다. 에이전트 홈 자체와 이를 혼동하거나 홈 전체를 문서 소스로 수집하지 않는다. |
| Git 프로젝트·작업 경로 | 현재 사용자 홈을 `~`로 축약하고 나머지 경로를 유지한다. 기준 위치·표시 별칭 등록 없이 여러 독립 폴더를 지원한다. | 공통 경로 표시 함수가 규칙을 소유한다. 실제 원본 작업 경로·과거 Usage 귀속은 유지하고 이 표시로 문서 수집 범위를 넓히지 않는다. |
| 문서·Local Context 위치 | 프로젝트 안팎의 여러 문서 폴더·개별 파일과 선택적 Notes를 등록한다. | 기존 Context 등록 DB가 경로·이름·읽기/검색 범위를 소유한다. 문서 수집은 이 등록에 따르며 Git 프로젝트나 에이전트 프로필 등록과 구분한다. |
| LocalBrain 자체 저장 위치 | 앱 설정·DB는 Application Support, private 파생 캐시는 Caches 등 기존 로컬 resolver를 사용한다. | 설정에서 위치·용량을 보여준다. 사용자 원본 경로와 별개이며 실행 중 데이터 루트 변경·물리적 이동은 OP-03 후속 범위다. |

기본 경로는 현재 사용자의 home에서 얻은 후보일 뿐이다. `~/.codex`, 별도 Codex 프로필, `~/Projects`나 개인별 짧은 문서 별칭을 필수 구조로 만들지 않는다. 경로 선택은 로컬 설정에 기록하고 기존 파일을 이동시키지 않는다. 별칭을 쓰는 경우 실제 경로와 구분하되, 별도 셸 별칭 관리 제품은 만들지 않는다. 소스 ID는 표시 이름이나 경로 변경과 독립적으로 유지한다.

## User Flows And Interaction Expectations

### First Launch And Existing Installation

1. 앱은 자신의 실행 환경으로 시작하고, 준비 중·실패·복구 상태를 창 안에서 설명한다. 터미널 실행을 기본 사용 경로로 요구하지 않는다.
2. 새 설치는 발견한 에이전트 홈/세션 위치 후보와 직접 선택을 제공한다. 후보 발견은 등록·수집 동의가 아니다. 특정 회사용 경로를 항상 등록하지 않는다.
3. 사용자는 소스 종류·이름·실제 세션 경로를 확인하고 Local Context를 선택적으로 추가한다. 프로젝트 경로 표시는 등록 없이 홈 축약 규칙을 적용한다. 각 위치는 별도 역할이며 빈 소스 목록으로 시작할 수 있다.
4. 기본 검색으로 시작하거나 로컬 AI 검색 모델을 선택한다. 모델 설치를 건너뛰어도 정상 완료이며 반복 팝업을 만들지 않는다.
5. 선택한 자료를 가져오는 진행과 소스별 오류를 보여준다. 실패한 한 소스가 다른 정상 소스의 읽기를 막지 않는다. 등록한 세션은 앱 실행 중 기본 10분 간격으로 갱신되며 설정에서 조정할 수 있음을 안내한다. 첫 가져오기와 예약 실행을 중복시키지 않고, 모델 설치 후 인덱싱은 가져온 허용 자료를 대상으로 한다.
6. 기존 설치는 설정·등록 소스·핀·Chart 선택·사용량·보존 기록을 이어받는다. 새 사용자용 기본값으로 덮어쓰거나 온보딩을 다시 강제하지 않는다. 호환 불가 시 기존 상태를 보존하고 복구 방법을 제시한다.
7. 첫 실행 안내는 실제 메인 화면 위의 단계형 설정 창으로 제공한다. 환영·세션·문서·검색 순서에 이전·다음·건너뛰기를 두고 입력한 경로는 다음으로 저장한다. 오류 시 입력과 단계를 유지한다. 마지막 완료 또는 나중에 설정으로 안내를 마치며, 그 전에 앱을 종료하면 기존 등록을 보존한 채 다음 실행에 안내를 다시 표시한다. [C10 후속 명세](../spec/spec-0137-first-run-local-setup.md#first-use-overlay-wizard--2026-10-23)가 세부 계약을 소유한다.

설정은 하단 `설정` 진입점으로 열고, 왼쪽 분류와 오른쪽 내용으로 구성한다. `⌘,`, 키보드 탐색, Escape, 닫은 뒤 원래 선택·스크롤·포커스 복귀를 제공한다. 좁은 창에서는 순차 탐색 구조를 사용하되 필수 항목을 숨기지 않는다. 기존 디자인 토큰·타이포그래피·오류 표현을 사용하고 새 화면군에 필요한 규칙은 소유 문서와 함께 검토한다.

경로는 네이티브 파일 선택과 직접 입력·붙여넣기를 제공하고 숨김 폴더도 선택할 수 있어야 한다. 저장 결과·실패·재시작 필요 여부는 실제 적용 상태와 일치해야 한다. 잘못된 값이나 저장 실패로 기존 설정을 잃지 않는다. 장시간 다운로드·인덱싱은 설정 창을 닫는 동작과 취소 동작을 구분한다.

일반 설정은 로컬 설정 파일을 따른다. 파일에 없는 항목만 기본값을 사용한다. 환경변수 우선 적용과 저장값/현재 적용값을 나누는 UI는 제공하지 않는다. 시작 화면 변경은 다음 실행부터, 시간대 변경은 저장 후 화면 갱신부터 적용한다. 기존 설정은 보존하고 버전 변화에 필요한 항목만 이전하며, 세션·검색·Context의 담당 값을 일반 TOML로 일괄 복제하지 않는다.

### Source Identity And Scope

도구 종류(`provider_kind`)는 파서와 정규화를 결정하고, 숫자 DB 기본키(`sources.id`, 설정의 `source_id`)는 가져온 기록의 소유를 결정한다. 문자열 `source_key`와 별도 내부 별칭은 현재 계약에서 제거했다. 표시 이름·색상·리스트 순서는 사용자 선택이며 같은 숫자 ID로 화면 전체에 투영한다. 기존 기록 ID와 고정 출처는 보존하고 레거시 키 읽기는 이전 과정에만 한정한다. 표시 이름과 경로를 이 두 역할로 대체하지 않는다. 같은 도구의 두 경로를 서로 다른 이름으로 등록해도 독립된 소스이며, 목록·Chart·핀·상세 출처·대시보드에서 같은 식별자와 표시 정보를 사용한다.

소스 수에 따라 필터를 버튼이나 선택 메뉴로 표현하되, `전체`와 소스별 범위가 일치해야 한다. 조회 선택만으로 동기화 범위나 원본을 바꾸지 않는다. 중복·겹친 경로, 접근 불가, 경로 이동, 새 소스 추가를 구분하고 기존 기록을 다른 소스로 조용히 재귀속하지 않는다.

경로를 재연결할 때는 같은 소스라는 확인과 기존 기록 보존 조건이 충족되어야 한다. 누락·오타·권한 거부·연결 해제는 원본 삭제나 기록 purge로 해석하지 않는다. 정상 스캔의 원본 소실 처리는 기존 소스 미러 계약과 구분해 설명한다. 별도 영구 보관 정책을 암묵적으로 추가하지 않는다.

### Periodic Session Synchronization

**기본 10분 간격·보조 수동 실행과 로컬 브라우저·배포 앱의 공통 적용은 사용자 요구다.** C13은 공통 FastAPI 백엔드의 지속적인 제품 기능으로 둔다. 기존 로컬 웹 실행(`localbrain serve`)과 Tauri 앱의 동봉 백엔드가 같은 수집·설정 규칙을 사용하며, 브라우저 탭이 열려 있어야만 실행되는 타이머로 만들지 않는다. 설정은 로컬에 남지만 실행은 백엔드가 살아 있는 동안에 한정한다.

아래는 C01/C02·C13과 후속 사용자 정정을 반영한 세션 동기화 계약이다. Local Context의 독립 주기와 공통 설정 분류는 [현재 설정 계약](../../policies/project/desktop-app-and-settings.md)이 소유한다. 10분은 사용자가 선택한 초기값이며 모든 자료 규모에서 최적이라는 성능 측정 결과가 아니다. `지금 동기화`는 기존 Sessions의 `동기화` 버튼 역할을 설명하는 표현이다.

| 항목 | 동작 기준안 |
| --- | --- |
| 설정과 소유 | 로컬 웹·배포 앱 모두 명시적인 저장값이 없으면 자동 동기화 켜짐·10분을 기본으로 한다. 기존 명시적 설정은 보존한다. 설정의 동기화 분류에서 세션과 Local Context 각각 10/20/30/60분·끄기 단일 선택기를 제공한다. 끄기를 선택해도 이전 간격은 보존한다. 기존 저장 간격과 세션 최초 기본값 10분을 보존하며 Context의 없는 항목은 켜짐·30분이다. 두 영역은 각각 완료 시점부터 다음 실행을 계산한다. 주기 설정은 일반 TOML과 공통 설정 레이어가 소유하며 브라우저·서버·앱 재시작 후에도 유지한다. 같은 로컬 데이터 저장소를 사용하는 실행은 같은 파일 값을 읽고 환경변수로 일반 설정을 덮어쓰지 않는다. 소스 등록은 세션 TOML, 소스별 최근 스캔 상태는 기존 로컬 DB의 sources/source_files가 소유한다. 전체 실행 이력을 누적하는 전용 테이블은 없다. 재생성할 수 있는 전체 수집 상태는 별도 로컬 `session-sync-state.json`에 두어 상태 기록만으로 검색 인덱스를 다시 준비하지 않는다. 같은 값을 두 저장소에 중복 저장하지 않는다. |
| 첫 실행·다시 실행 | 첫 등록 후 가져오기는 한 번 수행한다. 이후 웹 서버 또는 앱 백엔드 준비가 끝났을 때 자동 동기화가 켜져 있고 등록 소스가 있으며 실행 시점이 지났으면 한 번 갱신한다. 최근 완료 후 간격이 남아 있으면 남은 시간을 기다린다. 자동 동기화가 꺼져 있거나 소스 목록이 비어 있으면 예약 수집 작업을 만들지 않는다. UI를 제공할 수 있게 한 뒤 백그라운드에서 진행하며 실제 브라우저 접속을 기다리지 않는다. |
| 주기와 중복 방지 | 자동 또는 수동 작업이 끝난 시점부터 다음 간격을 계산한다. 실패한 작업도 즉시 반복하지 않는다. 공통 백엔드가 실행 상태를 소유하며 자동·수동·첫 가져오기가 겹치면 진행 중 작업을 보여주고 중복 실행이나 누적 대기열을 만들지 않는다. 브라우저 탭·창·재접속으로 실행 횟수가 늘지 않는다. 같은 데이터 저장소에 웹 서버와 앱 백엔드를 함께 실행하는 경우도 단일 실행 소유 계약에 포함한다. |
| 수집 범위와 비용 | 등록한 로컬 Session 소스를 대상으로 기존 증분 수집을 재사용한다. 변하지 않고 처리 계약·파생 근거가 유효한 파일은 재처리를 생략하고 필요한 복구는 유지한다. 매 주기 전체 재수집을 강제하지 않는다. 파일 후보 탐색 비용은 남으므로 자료 수·변경량별 실행 시간과 자원 사용을 확인한다. 목록의 조회 필터는 수집 범위를 바꾸지 않는다. 세션 타이머는 Context·Notes·Git·Atlassian 수집이나 에이전트를 호출하지 않는다. Run 190의 별도 Context 타이머는 사용자가 등록한 Context 범위만 기존 수집기로 처리한다. |
| 창 닫기·완전 종료·잠자기 | 로컬 웹은 브라우저 탭이나 브라우저를 닫아도 서버가 실행 중이면 예약 동기화가 계속된다. 서버 프로세스를 종료하면 예약도 중지한다. Tauri 앱은 창만 닫으면 백엔드가 살아 있는 동안 계속되며, 앱의 `⌘Q`는 다음 예약과 동봉 백엔드를 함께 종료한다. 두 실행 방식 모두 종료 시 진행 중 상태를 복구 가능하게 마무리한다. 잠든 Mac을 깨우지 않으며, 깨어났을 때 실행 시점이 지났으면 한 번만 갱신한다. 밀린 횟수만큼 연속 실행하지 않는다. 로그인 자동 시작·별도 daemon은 추가하지 않는다. |
| 설정 적용 | 끄기는 새 자동 실행 예약을 즉시 중지하며 이미 실행 중인 작업은 정상 마무리한다. 수동 실행은 계속 사용할 수 있다. 주기 변경·다시 켜기는 마지막 완료 시점과 현재 상태로 다음 실행을 다시 계산하고, 이미 시점이 지난 경우에도 한 번만 실행한다. 다음 예약도 설정 파일의 주기·켜기/끄기 값을 사용한다. |
| 상태와 오류 | 진행 중·최근 시도·마지막 성공·다음 실행과 소스별 실패를 구분한다. 한 소스의 접근 불가나 실패가 다른 정상 소스의 수집을 막지 않으며, 실패로 마지막 성공 시각이나 기존 데이터를 덮어쓰지 않는다. 자동 실패는 상태에 남기고 다음 주기 또는 수동 요청에서 재시도한다. 반복 팝업을 만들지 않는다. 정상 스캔에서 사라진 원본을 정리하는 기존 미러 계약은 유지한다. |
| 목록·대시보드·읽기 | 기존 Sessions `동기화` 버튼을 유지한다. 설정에는 주기 선택만 두고 전체 동기화 상태·시각·수동 버튼 카드는 두지 않는다. 최근 상태는 로컬에 계속 기록하며 소스별 오류는 소스 상태에서 확인한다. 공통 화면의 자동 동기화 상태 표시줄과 `업데이트된 기록 보기` 링크는 두지 않는다. 자동 완료만으로 전체 페이지를 강제 reload하거나 스크롤·필터·선택·포커스·읽던 상세를 초기화하지 않는다. 화면을 다시 열거나 명시적으로 새로고침할 때 최신 자료를 표시한다. |
| 검색·복구와 조정 | 선택한 검색 기능의 기존 자료 허용·인덱스 갱신 계약을 유지한다. 변경 없는 스캔의 상태 기록만으로 전체 재임베딩을 반복하거나 모델을 자동 설치하지 않는다. 유효하지 않은 계약·인덱스의 필요한 재준비는 별개다. 복원·경로 재연결 등 배타적인 상태 변경 중에는 새 수집을 시작하지 않고, 완료 후 현재 등록·설정으로 한 번만 재평가한다. 원본·에이전트 설정·인증 파일은 수정하지 않는다. |

이 기능은 로컬 세션 자료의 최신성을 유지한다. 설치형에서 제외한 `자동 작업`의 작업 생성·에이전트 실행·외부 통신 기능을 포함하지 않는다. 수동 버튼의 기존 완료 후 전체 reload나 검색 서비스의 DB 변경 감지 주기를 그대로 주기 동기화 UX로 사용하지 않는다.

### Search And Optional Model

기본 검색은 사용자 선택에 따라 **deprecated `/search`의 기존 FTS5 키워드 검색 동작을 재사용**한다. 현재 코드는 검색어 토큰을 최대 12개까지 AND 조건으로 묶어 `MATCH`하고 결과·발췌문을 반환한다. “LIKE”를 새 SQL 부분 문자열 검색 요구로 확대하거나 새 검색 품질 프로젝트를 추가하지 않는다. 기존 결과의 제목·경로·발췌와 세션/문서 진입을 유지하면서 통합 검색 UI에 연결한다.

재사용 범위는 검색 동작이며 설치형의 자료 허용 범위는 별도로 적용한다. 현재 legacy 경로의 Atlassian 결과·필터·Workstream 필터는 설치형에서 제외한다. 유지보수 Run·검색 캐시·비활성/읽기 불가 Context 등을 재노출하지 않으며 허용된 세션·등록 문서만 검색한다. 기존 자연어 검색의 키워드 진입 제외 계약을 바꾸는 작업은 승인된 후속 Feature에서 수행한다.

공유 검색 입력은 하나를 유지하는 안이다. AI 검색을 선택했고 준비가 완료되면 의미 기반 검색을 사용한다. 기본 검색으로 동작할 때는 의미 검색이 수행된 것처럼 표시하지 않는다. 기본 검색으로의 복구는 사용자가 입력한 질의와 선택 범위를 보존하며, 모델 미준비·실패를 결과 0건으로 표시하지 않는다. 모델이 정상이어도 관련 결과가 없다는 이유만으로 검색 종류나 범위를 조용히 바꾸지 않는다.

| 상태 | 사용자가 이해할 결과와 다음 행동 |
| --- | --- |
| 미선택·미설치 | 기본 검색 사용. 모델 설치는 선택이며 일반 탐색을 막지 않는다. |
| 다운로드 중·중단·실패 | 진행·예상 용량·취소·재시도/재개를 확인한다. 기본 검색은 계속 사용한다. |
| 파일 검증 또는 실행 환경 오류 | 다운로드 완료와 실행 가능을 구분하고 복구를 안내한다. 원본과 기존 기본 검색을 보존한다. |
| 모델 준비·인덱싱 중 | 가져온 자료의 검색 준비 범위를 표시한다. 모델 설치만으로 전체 자료 검색 준비가 끝났다고 표시하지 않는다. |
| AI 검색 사용 가능 | 선택한 모델과 호환 인덱스로 로컬 의미 검색을 실행한다. 검색 질의·개인 자료를 원격 fallback으로 전송하지 않는다. |
| 갱신·인덱스 손상·모델 사용 해제 | 현재 허용되고 유효한 자료만 반환한다. 기존 완성 세대 사용·기본 검색·명시적 재준비를 상태에 맞게 구분하며, 데이터 삭제로 대신하지 않는다. |

설치 안내에는 공개 모델 파일 약 1.21GB와 별도로 실행 라이브러리·private 인덱스·재생성 중 임시 공간이 필요함을 설명한다. 모델 ID·revision·검증 정보와 공개 가중치 재사용 경계를 유지한다. 검색 활성화 후 Sync로 가져온 자료의 변경을 반영하는 기존 동작을 유지하며, 이를 원본 파일의 상시 감시라고 설명하지 않는다.

### Storage, Recovery And App Lifecycle

| 소유 | 저장과 변경 원칙 |
| --- | --- |
| 앱 프로그램 | `.app`의 실행 파일·라이브러리·정적 리소스. 사용자 설정·DB·자료를 묶지 않는다. |
| 영속 사용자 데이터 | 기존 Application Support의 DB, 설정, 사용자 선택, 보존할 보고서. 앱 교체나 캐시 정리로 삭제하지 않는다. |
| 설정 값 | 일반 설정 TOML을 추가하고 기존 세션 TOML·검색 JSON·Context DB의 값별 정본을 유지한다. 같은 항목을 두 저장소에서 각각 수정할 수 있게 하지 않는다. |
| private 파생 자료 | 기존 Caches의 검색 인덱스·미리보기. 재생성 가능해도 개인 데이터이며, 실행 중인 작업과 소유 불명 파일은 정리하지 않는다. |
| 공개 모델 | 기존 공유 Hub 캐시와 앱의 설치 등록 정보를 구분한다. 앱에서 사용 해제하는 행동이 다른 앱의 공유 가중치 삭제로 이어지지 않는다. |
| 개발 근거 | 별도 개발 아카이브의 평가·진단 자료. 설치 데이터나 배포 자산으로 편입하지 않는다. |

설정 버전·기존 값 보존·파일 필드와 기본값·적용 조건을 C01에서 명시한다. 기존 명시적 경로를 보존하고, 다른 설치의 데이터를 새 빈 DB로 바꾸어 정상 시작한 것처럼 보이지 않아야 한다. 데이터·캐시 위치를 보여주는 것과 실제로 옮기는 권한은 구분한다.

OP-09에서 선택한 백업·복원은 같은 Mac의 앱 소유 영속 상태를 일관되게 보존·복구하는 범위다. 백업에 포함되는 설정·DB·보존 기록과 제외되는 외부 원본·공유 모델·재생성 캐시를 표시한다. 실행 중 DB 파일 하나를 무조건 복사하는 동작을 백업 성공으로 간주하지 않는다. 복원 실패는 기존 상태를 보존해야 한다. OP-03에서 보류한 다른 위치·Mac으로의 이동이나 경로 자동 치환을 백업·복원에 포함하지 않는다.

앱이 시작·준비 확인·단일 인스턴스·로컬 포트·종료를 소유한다. 창 닫기는 창만 닫고 사용자가 시작한 가져오기·다운로드·인덱싱과 켜 둔 주기적 세션 동기화는 계속하며, Dock에서 다시 열면 기존 창을 복원한다. `⌘Q`는 앱 완전 종료로, 다음 예약을 중지하고 백엔드·활성 작업을 완료하거나 복구 가능한 상태로 중단한다. 잠자기·재개·충돌 후 상태 복구를 다루되 밀린 주기 실행을 누적 재생하지 않는다. 로그인 시 자동 시작·별도 상주 daemon은 첫 범위에 넣지 않는다. 내부 서버는 로컬 통신 경계를 유지한다. 권한은 사용자가 선택한 소스 기능에 필요한 시점에 요청하고, 거부·철회 후에도 앱의 다른 기능은 사용할 수 있어야 한다.

앱 업데이트는 영속 데이터와 설정의 호환·이전·복구를 함께 판단한다. GUI에서 외부 CLI를 사용하는 기능을 포함하기로 바꾸면 실행 파일 경로·프로필·인증 의존성을 별도로 설계해야 하며, 셸 PATH에 기대어 기본 세션 읽기를 막아서는 안 된다.

### Distribution Preparation — OP-10

아래는 기존 **초기 테스트 전달 단계**의 계약이다. `2026-10-20`에 확정한
[공개 배포 목표](#public-distribution-goal--2026-10-20)의 완료 기준을 대신하지 않는다.

현재 목표는 팀원에게 빠르게 전달해 쓰게 하는 테스트 앱이다. 흐름은 **로컬에서 패키징한 앱 확인 → 내부 Drive에 ZIP 공유 → 팀원이 다운로드·압축 해제 → `LocalBrain.app` 더블클릭 → 자신의 경로 등록**이다. Applications에 복사하는 것은 선택이며 설치 마법사·DMG를 요구하지 않는다.

| 항목 | 첫 테스트의 기준안 |
| --- | --- |
| 프로그램 형태 | Finder에서 앱 하나로 보이는 `.app` 번들. 내부에는 Tauri 실행 파일·Python 백엔드·검색 실행 라이브러리·화면 리소스가 있다. 물리적으로 한 개의 Mach-O 바이너리로 합치는 요구는 아니다. |
| 전달 | `.app` 하나를 ZIP에 담아 내부 Drive로 공유한다. 팀원은 로컬에 내려받아 실행하며 소스 checkout·Python·uv·Homebrew·개발자 계정을 준비하지 않는다. 사용자 설정·DB·세션·문서·개인 캐시는 ZIP이나 공유 Drive에 포함하지 않는다. 실제 전달·실행 근거는 아직 없다. |
| 실행과 데이터 | 프로그램 리소스는 번들 위치를 기준으로 찾고 쓰기 가능한 사용자 데이터는 기존 Application Support·Caches에 둔다. 앱이 놓인 폴더나 개발자의 작업 디렉터리에 의존하지 않는다. 앱 파일만 복사해도 사용자 데이터가 함께 이전되는 방식은 OP-03 후속이다. |

| 교체 | 앱을 완전히 종료한 뒤 새 ZIP의 앱으로 수동 교체한다. 사용자 설정·DB는 보존하며 앱 삭제와 사용자 데이터 삭제를 구분한다. |

확인은 두 단계로 구분한다. 먼저 개발자의 Mac에서 개발 서버 대신 완성된 `.app` 자체를 실행해 번들 리소스·백엔드·종료를 확인한다. 다음으로 지원 대상 Apple Silicon 팀원 Mac 한 대에서 같은 ZIP을 내부 Drive에서 내려받아, 개발 checkout이나 사용자 설치 Python에 의존하지 않는 시작·본인 경로 등록·세션/Context 읽기·대시보드·모델 없는 검색을 확인한다. 각 팀원의 설정·자료는 해당 Mac에만 남는다. 개발자의 개인 경로·기존 캐시·설치 라이브러리 때문에 우연히 성공한 상태를 팀원 실행 가능의 근거로 삼지 않는다. 첫 전달 확인은 가벼운 사용 확인이며 전체 Mac 환경의 호환 보증으로 확대하지 않는다.

### Deferred Identified Distribution

Developer ID와 공증은 초기 ad-hoc 테스트본의 선행 조건에서 제외했지만,
`2026-10-20`에 명시한 **공개 배포 목표를 달성하기 위한 준비사항**이다. 아래 항목의
실제 수행은 아직 남아 있다. `.app` + ZIP을 유지할 수 있고 DMG·App Store 등록은
필수가 아니다. 이 준비를 기존 테스트 완료 근거에 포함해 완료로 간주하지 않는다.

| 추후 항목 | 그 방식을 선택할 경우의 준비 |
| --- | --- |
| Apple Developer Program | 개인/조직 가입과 이중 인증된 Apple Account. 공식 연회비는 99 USD이고 지역별 실제 결제 금액은 가입 시 확인한다. |
| Developer ID Application | App Store 외부 배포용 인증서를 발급해 Mac Keychain에 보관하고 Tauri 서명에 연결한다. 받는 사용자에게 개발자 계정을 요구하지 않는다. |
| 공증 | 앱·동봉 실행 요소의 서명과 hardened runtime·권한을 갖춘 배포 프로그램을 Apple에 제출하고 발급 티켓을 첨부한다. 개인 설정·DB·세션·문서는 포함하지 않는다. |
| 전달·업데이트 | DMG·다운로드 채널·업데이트 안내를 필요에 따라 정한다. 앱 교체 시 데이터 호환·복구 원칙은 유지한다. 자동 updater는 별도 검토다. |

조건·비용은 [Apple 등록 안내](https://developer.apple.com/programs/enroll/), 인증서 연결은 [Tauri macOS signing](https://v2.tauri.app/distribute/sign/macos/), 공증은 [Apple Developer ID](https://developer.apple.com/developer-id/)의 `2026-10-18` 확인 내용이다. 실제 가입·결제·서명·공증 업로드·공개를 수행한 기록은 아니다.

## Constraints

- 이 PRD는 기존 자연어 검색의 **일반 탐색에서 키워드 검색을 제외하는 규칙**과, 검증 후반에 패키징을 두던 순서를 바꾸려는 새 경계다. 현재 승인된 구현에서 키워드/AI 검색 진입과 패키징 순서를 변경하며 해당 소유 문서를 함께 갱신한다.
- 기존 세션 ID, 소스 ID, 핀, Chart 사용자 선택, 원문 출처, 고정된 Usage 귀속·가격 근거, 보존 보고서를 일반화 과정에서 재생성하거나 합치지 않는다.
- 대시보드 비용은 구독 청구액이 아닌 API 환산 추정치이며, 미가격·부분 집계·자료 범위 한계를 유지한다. 숨기는 Insights의 스킬 통계도 기존 의미는 사용·참조 세션 수이며 실행 성공 횟수로 바꾸지 않는다.
- 원본 읽기는 승인된 로컬 소스 범위에 한정한다. 소스 등록을 원본 편집이나 외부 분석·업로드 동의로 해석하지 않는다.
- 공개 문서·배포물·검증 fixture는 공통 코드와 합성 자료만 포함한다. 원본·사용자 설정·자격 증명·개인 인덱스·스크린샷·진단 결과를 배포하지 않는다.
- 기존 저장소 resolver와 소유·권한·복구 규칙을 재사용한다. 공유 모델 파일과 private 파생 자료, 사용자 의도와 재생성 캐시를 섞지 않는다.
- 현재 코드·문서 검토는 실제 desktop 실행 근거가 아니다. Apple Silicon에서의 모델 실행 근거를 Intel·모든 macOS·모든 corpus의 정확도와 성능으로 확대하지 않는다.
- 보이는 화면 작업은 `frontend-product` 또는 `fullstack-product`로 분류하고 Design·Functional·Interaction Evaluation을 적용한다. 이 문서 작성은 계획 작업이며 평가 실행 결과를 만들지 않는다.

### Personalization Boundaries

사용자가 자신의 폴더 구조를 앱에 맞춰 재배치하지 않고도 사용할 수 있게 한다. 기본값으로 시작하고 필요한 소스와 표시만 조정하는 방향이다.

| 영역 | 유지할 사용자 선택과 앱의 책임 |
| --- | --- |
| 세션 소스 | Codex·Claude의 사용자 지정 이름, 에이전트 홈, 실제 세션 위치를 여러 개 등록한다. 기존 안정된 소스 ID와 재연결 계약을 유지한다. 특정 회사 프로필이나 공통 상위 폴더를 요구하지 않는다. |
| 경로 표시 | 현재 사용자의 홈을 자동으로 알아내 `~`로 축약하는 고정 규칙을 적용한다. `~/Projects/app`, `~/Project1`, `~/Project2`를 같은 규칙으로 표시하며, 짧게 표시하기 위한 기준 위치 등록을 요구하지 않는다. |
| 프로젝트 분류 | 원본 작업 경로와 기존 프로젝트 귀속 근거를 유지한다. 표시 문자열을 프로젝트 ID로 사용하거나 이름이 같은 폴더를 자동으로 합치지 않는다. |
| Local Context | 사용자가 등록한 폴더·파일·선택적 Notes의 범위만 수집한다. 경로 표시나 프로젝트 분류를 위해 홈 전체 또는 프로젝트 문서를 자동 수집하지 않는다. |
| 일반 설정 | 시작 화면·시간대·동기화 등 기존 개인 설정을 로컬에 보존한다. 공통 설정 레이어와 값별 단일 소유, 파일 저장값 → 없는 항목의 기본값을 사용하고 환경변수로 일반 설정을 덮어쓰지 않는다. 세션 TOML·검색 JSON·Context DB의 값을 일반 설정에 중복 저장하지 않는다. |
| 앱과 데이터 | 공통 웹 실행과 배포 앱에 같은 규칙을 적용한다. 설정·DB·원본·캐시는 각 Mac의 기존 로컬 소유를 유지한다. 앱 교체와 사용자 데이터 이동을 구분하고 물리적 이동은 계속 후속 범위로 둔다. |

기존 Tauri·Apple Silicon·모델 선택성·10분 기본 동기화와 설치형의 기능 제외 범위는 유지한다. 경로를 짧게 표시하는 요구만으로 새 프로젝트 등록 시스템, 폴더 이동, 원격 동기화, 테마·다국어 설정을 추가하지 않는다.

### Fixed Home-Abbreviated Display

다음은 현재 사용자의 홈이 `/Users/<demo>`인 합성 예시다.

| 실제 경로 | 공통 표시 |
| --- | --- |
| `/Users/<demo>/Projects/app` | `~/Projects/app` |
| `/Users/<demo>/Project1` | `~/Project1` |
| `/Users/<demo>/Project2` | `~/Project2` |
| `/Users/<demo>` | `~` |
| `/Volumes/Work/app` | `/Volumes/Work/app` |
| `/Users/<other>/app` | `/Users/<other>/app` |

- 홈은 실행 사용자의 실제 홈에서 얻는다. 특정 사용자명이나 `/Users/<이름>` 전체를 일괄 치환하지 않는다. 홈 자신 또는 경로 구성요소 기준으로 그 아래에 있는 경로만 축약한다. 예를 들어 `/Users/<demo2>/app`은 `/Users/<demo>`의 하위 경로가 아니다.
- 홈 밖의 경로는 전체 경로를 유지한다. 폴더가 일시적으로 없어도 이미 알고 있는 경로를 표시할 수 있어야 한다. 경로가 없는 기록에는 임의의 홈·현재 디렉터리를 채워 넣지 않는다.
- 화면 표시는 원본 경로·저장된 절대 경로·소스/세션 식별자·과거 사용량 귀속을 바꾸지 않는다. 실제 파일 접근과 동일성 판정은 각 도메인의 기존 경로 계약을 따른다.
- **경로 표시 선택과 기준 위치 등록 UI를 없앤다.** 앞서 제안한 `홈 경로 줄여 표시 (~)` / `전체 경로` 선택도 제공하지 않는다. 일반 설정에는 시작 화면·시간대의 짧은 드롭다운 두 개를 유지한다. 동기화는 후속 Run 190–191에서 독립 분류와 영역별 단일 선택기로 옮겼다.
- Sessions·상세·Dashboard·Context·소스 설정에서 실제 경로를 보여주는 부분에 같은 축약 규칙을 적용하는 방향으로 정리한다. 파일 선택·편집·복사에 필요한 실제 경로도 확인할 수 있어야 하며, 문서 제목·사용자 지정 소스 이름을 경로로 대체하지 않는다.

### Project Labels And Attribution

경로를 표시하는 규칙과 어떤 세션을 같은 프로젝트로 집계하는지는 별개의 계약이다. 현재 Sessions의 Projects는 작업 폴더, Chart는 기록된 실행 폴더, Dashboard의 Usage는 최초 관측 당시 Git 루트 또는 작업 폴더에 기반한다. 홈 축약만으로 이 분류들이 동일해지지는 않는다.

- **`.`:** 이전 수집기의 `~/Projects` 고정 표시 기준은 해당 폴더 자체를 `.`로 만들었다. 이번 수정은 그 기준을 제거하고 실제 경로가 남아 있는 기록을 `~/Projects`처럼 표시한다. 상위 폴더에서 실행한 세션을 특정 하위 프로젝트에 임의로 배정하지 않는다.
- **`Unassigned`:** 프로젝트 귀속 정보가 없는 기록이다. 홈 축약으로 해결되는 상태가 아니다. 2026-10-20 승인에 따라 Project는 `session_class=work`인 일반 작업과 하위 세션만 포함하고, 실제 미귀속 작업은 `프로젝트 미지정`으로 표시한다. 분석·Maintenance는 프로젝트 귀속 유무에 관계없이 Project 행·합계·비율 분모에서 제외하며 전체 사용량·추이·Source/Model에는 유지한다. `By Project / Project` 명칭과 홈을 포함한 Git 루트/실행 폴더 기준을 유지한다. 저장된 귀속·사용량·비용은 변경하지 않으며 설치형 Insights도 계속 숨긴다.
- 경로 이름과 안내 문구를 명확하게 하는 작업을 우선 검토한다. 여러 체크아웃·worktree를 하나의 논리 프로젝트로 묶거나 과거 Usage를 재분류하는 기능은 별도 요구와 검토가 생길 때 다룬다. 앞서 제안한 독립 프로젝트 ID·수동 연결 시스템은 이번 홈 축약을 위해 필요한 선행 조건이 아니다.

### Adopted Scope And Acceptance Seeds

후속 사용자 정정으로 표시 선택과 기준 위치 개념의 제거를 확정했다. 적용 경계는 다음과 같다.

1. **기존 설정 호환:** `project_display`·`projects`는 적용값과 API 수정 대상에서 제외하고 기존 TOML 값은 비활성 항목으로 보존한다. `LOCALBRAIN_PROJECT_DISPLAY`도 적용하지 않는다. 새 설정에는 이 항목들을 만들지 않으며 잘못된 과거 필드 값도 다른 유효한 설정의 읽기·저장을 막지 않는다.
2. **프로젝트 설명 범위:** C07 수정은 홈 축약과 `~/Projects` 고정 표시 기준 제거에 이어 Dashboard의 Project를 일반 작업·하위 세션만으로 집계한다. 분석·Maintenance는 전체 사용량에 유지하고 Project 행·합계·비율 분모에서 제외한다. 원본·저장된 프로젝트 귀속과 전체 사용량·비용 합계는 보존한다. 화면 간 프로젝트 분류 통합과 과거 귀속 변경은 별도 요구가 생길 때 Chart의 실행 폴더 의미와 함께 검토한다.

수용 조건은 다음과 같다. 항목별 실제 검증과 그 한계는 C07 Run·평가 기록에서 확인한다.

- 서로 다른 사용자 홈, 여러 독립 프로젝트 폴더, 홈 자체, 홈과 문자열 접두사만 같은 폴더, 외장 볼륨, 다른 사용자 홈, 현재 접근할 수 없는 폴더에서도 정한 표시 규칙을 따른다.
- 이름이 같은 다른 폴더는 경로로 구분되고 표시 변경 전후의 세션·소스 ID, 프로젝트 귀속, 사용량·비용 합계가 같다.

- 원본이나 등록 경로를 이동하지 않고 세션·문서 수집 범위를 넓히지 않는다. 기존 설정의 호환·저장 실패 보존을 유지하며 일반 설정의 환경변수 덮어쓰기를 제거한다.
