## 결론

이 문서는 당시의 v2 비교 기록이다. 이후 [일반 업무 검색 개선](eval-0123-functional-general-work-search.md)이
원문·핵심 표현 결합을 기본 경로로 채택했다. 아래 수치는 과거 측정으로 보존한다.

단어가 겹친다는 이유로 약한 후보가 강한 의미 근거보다 먼저 나오는 문제를
줄였다. 기존에는 의미 검색과 어휘 검색의 **순위**를 합쳤다. 이제는 분자의
**의미 유사도**를 그대로 비교해 원문을 정렬한다. 정확한 단일 영문 식별자를
찾는 어휘 보조 경로는 유지한다. 모델, 질의 원문, 문서 분해, 벡터, cutoff 0.45는
그대로이므로 추가 모델·개인 학습·문서 재임베딩이 필요하지 않다.

관련 자료가 앞에 나오는 정도는 합성 평가에서 좋아졌다. 개인 자료에서는
일부 관련 세션의 순위가 내려갔고, 넓은 주제와 중의어의 한계도 남아 있다.
측정 수치와 개별 회귀를 아래에 함께 기록한다.

후속 사용자 확인에 따라 평가의 우선순위를 명확히 한다. 목표는 **쓸모 있는
관련 자료를 상위에서 찾고 빠르게 원문으로 이어가는 자연어 검색**이다.
100% 분류 정확도나 정답 없는 질문의 오탐 0건을 수용 조건으로 삼지 않는다.
오탐 수치는 탐색 부담을 살피는 참고 지표로 유지한다. 개선 우선순위는
유용한 자료의 누락, 무관한 상위 결과가 유용한 결과를 밀어내는 문제,
여러 관련 원문의 회수와 응답 시간에 둔다. 이 해석 보완은 아래의 측정값이나
검증 범위를 바꾸거나 추가 실험을 수행했다는 뜻이 아니다.

## 무엇을 비교했나

동일한 Qwen3-Embedding-0.6B, 본문 목표 512토큰, 512차원, float32, MPS에서
기존 RRF와 의미 유사도 정렬을 비교했다. 어휘 보너스 0/0.03/0.05/0.08도
고정 후보로 비교했다. 새 개발 세트에서는0과0.03의 순위 지표가 같았고,
기존 선택 세트에서는0의 회수율과 순위 지표가 가장 높아 **0을 선택**했다.
이는 어휘 점수의 단위를 cosine에 그대로 더한 비교가 아니다. 보너스 후보는
`bonus * 60 / (60 + lexical_rank)`로 상한을 둔 실험이었다.

새 fixture는 실제 개인 문서를 복사하거나 바꿔 만든 자료가 아니다. 화면 배치와
야간 배치, 개발 기록과 상품 단어 목록, 인증 토큰과 문장 토큰, DB 색인과 책
색인 등을 구분하는 합성 원문을 직접 작성했다. 단어 목록 자체를 찾는 질문도
넣었으며 해당 두 질문의 첫 결과는 전후 모두 맞았다.

새 holdout은 인증서/수료증, 셸/조개껍데기, 서버 포트/항구, 장치 드라이버/운전자
등 별도 주제로 미리 작성했다. 선택을 고정한 뒤 처음 모델 결과를 확인했다.
처음 고정한 fixture와 최종 평가 fixture의 SHA256은 동일하다:
`9aebf364ed7d36c475c959dce4942db8531494ae4f7f16013feef4dc049e3c25`.
결과를 본 뒤 기대 정답이나 선택한 순위 방식을 바꾸지 않았다.

## 이해하기 쉬운 결과

여기서 “첫 결과가 맞았다”는 작성해 둔 관련 원문 중 하나가 1위였다는 뜻이다.
전체 결과 목록이 모두 맞았다는 뜻은 아니다. 분모에는 정답이 있는 질문만 넣었다.

| 평가 자료 | 원문 / 전체 질문 / 정답 있는 질문 | 기존 첫 결과 정답 | 개선 후 첫 결과 정답 |
| --- | --- | --- | --- |
| 이전 기본값 선택에 사용한 자료 |72 /27 /23 |20/23 |22/23 |
| 이번 중의어·단어 목록 개발 자료 |48 /29 /26 |24/26 |25/26 |
| 이전에 이미 관측한 별도 자료: 이번에는 회귀 확인 |24 /13 /10 |8/10 |9/10 |
| 이번 선택 후 처음 확인한 새 holdout |32 /19 /16 |16/16 |16/16 |

새 holdout은 첫 결과 적중률이 이미 같았지만, 두 번째 이후의 관련 원문 순서도
고려하는 nDCG@10이96.33%에서99.31%로 좋아졌다. 이전 선택 자료에서는
상위 10개에 포함된 관련 원문의 비율인 Recall@10이83.33%에서86.96%로 늘었다.
다른 세 세트의 Recall@10은 유지됐다. 상위 10개에 하나라도 정답이 있는 질문의
비율도 모든 세트에서 유지됐다.

| 자료 | Recall@10 전 → 후 | nDCG@10 전 → 후 | 반환 정밀도 전 → 후 | 정답 없는 질문에서 오탐 전 → 후 |
| --- | --- | --- | --- | --- |
| 이전 선택 자료 |83.33 →86.96% |84.39 →88.08% |56.81 →58.66% |0/4 →0/4 |
| 이번 개발 자료 |98.08 →98.08% |92.16 →96.42% |64.83 →64.83% |1/3 →1/3 |
| 이전 관측 자료 |96.67 →96.67% |88.02 →90.83% |29.05 →29.05% |0/3 →0/3 |
| 새 holdout |100 →100% |96.33 →99.31% |63.22 →63.22% |0/3 →0/3 |

반환 정밀도는 최대 10개 중 실제 반환한 개수로 나눈 질문별 정답 비율을 평균한다.
빈 결과는 0으로 계산하고 정답 없는 질문도 이 평균에 포함한다. Recall/Hit/nDCG는
정답 있는 질문에 대해서만 평균한다. 따라서 반환 정밀도를 개인 검색의 정답 확률로
해석하면 안 된다. 모든 세트의 정답 있는 질문에서 빈 결과는 전후 0건이었다.

## 실제 로컬 자료에서 확인한 점

명시적으로 선택한 질의만 로컬에서 비교했다. 사용자에게 받은 기대 주제와
primary가 연결한 대표 원문을 구분하여 기존 Development 영역에 보관했다.
주제 설명은 사람이 모든 원문의 관련 여부를 판정한 정답표와 다르다.

- 앱 개발 질문에서 단어 목록이 1위에서 4위로 내려갔고 실제 개발 세션이 2위에서
  1위로 올라갔다. 목록 자체를 검색 대상에서 제거한 것은 아니다.
- 사용자가 알려준 넓은 주제 질문에서는 일부 관련 원문이 올라오고 다른 관련
  원문은 내려왔다. 모든 기대 자료의 회수가 좋아졌다고 판정하지 않는다.
- 실제 문서의 중의어 질문에서는 같은 오답이 상위에 남았다. 합성 화면 배치 사례의
  순위 개선이 실제 개인 문서 전체의 의미 구분을 해결했다는 근거가 되지 않는다.
- 모델을 준비한 상태에서 7개 명시 질의를 각 3회, 방식별 21회 측정했다. 결과 캐시 없이
  순서를 교차했고 완료된 MPS 작업을 포함했다. 새 방식의 중앙값과95백분위가 모두
  짧아졌다. 정확한 개인 측정값은 private receipt가 소유한다. HTTP/브라우저 전체
  시간이나 다른 기기의 보장값이 아니다.
- 비교 동안 기존 색인 파일의 크기·수정시각과 정규화 DB/WAL 관측값은 변하지 않았다.
  문서 인코딩은 0회였고 기존 세대 그대로 검색했다. 모든 과거 색인·분해·공간 비용을
  이번에 다시 측정했다는 뜻은 아니다.

## 회귀 및 화면 확인

모델 없이 동작을 고정하는 테스트와 실제 Qwen 품질 비교를 구분했다.
새 테스트는 약한 단어 일치의 과도한 승격 방지, 정확한 식별자의 cutoff 예외,
범위·revision 제외를 어휘 후보 500개 제한보다 먼저 적용하는 조건, 반복 분자의
부모 점수·중복 근거·페이지 순서 불변을 확인한다.

현재 서버를 같은 로컬 주소로 재시작한 뒤 브라우저에서 사용자의 문장을 입력하고
검색 버튼으로 제출했다. 준비 완료, 바뀐 원문 순서, Session 조건, 경고·넘침 없음과
콘솔 오류 없음을 확인했다. 추가 질의의 문서/세션 구분과200응답, 실제 근거의
메시지 anchor 및 검색 복귀 링크, 기존 키워드 검색200응답도 확인했다.
화면 배치나 새 버튼은 변경하지 않았다. 전체 회귀 1,110개가 21.098초에 통과했고,
그중 자연어 검색 동작/HTTP 검사는 34개다. 초기에 새 테스트의 가상 인코더가
미지의 문자열을 같은 축으로 표현하여 기대값이 틀린 1건이 있었으며, 의미 점수가
0인 조건을 명시하도록 테스트를 고친 뒤 전체를 다시 통과했다. 최종 저장소 검사 결과는 RUN-159의
closeout을 따른다. 이번에는 독립 설치 패키지를 새로 빌드하지 않았다.
이전 설치 검증을 이번 순위 변경의 재검증으로 표시하지 않는다.

## 남은 한계와 재개 조건

- 이번 개발 세트에서 정답이 없는 종이접기 질문은 전후 모두 오탐이었다.
  cutoff를 높여 지우면 관련 자료도 잃을 수 있어 그대로 보고한다. 이 사례만으로
  제품 수용을 막거나 추가 튜닝을 요구하지 않으며, 실제 탐색 부담과 유용한 자료의
  회수를 함께 보고 우선순위를 정한다.
- DB 조회를 빠르게 하는 색인을 묻는 한국어 질문에서는 책의 색인이 먼저 나왔다.
  이전 관측 자료에서는 전체 지표가 좋아졌어도 복원 검증 문서 질문의1위가
  새로 틀렸다. 평균 개선이 개별 질문의 퇴보를 가리지 않도록 per-query 결과를 남겼다.
- 넓은 주제를 구체적인 업무 하위 주제 전체로 확장하는 문제와 실제 문서의 동음·다의어
  문제는 남아 있다. 이번 변경으로 자연어 조건을 추가 해석하거나 주제를 자동 확장하지 않는다.
- 추가 개선은 고정한 개인 관련/무관 판정과 별도 새 검증 자료를 갖고 판단해야 한다.
  작은 후보 집합의 reranker나 질의 표현 개선은 비용·누락·오탐을 다시 측정할 후보이며,
  이번 기본 경로에 추가하거나 효과가 검증됐다고 표시하지 않는다.
- 모든 품질 자료는 작성된 소규모 세트다. 한국어 전체, 다른 Mac/Windows, 다른 사람의
  자료에서 같은 성능을 보장하지 않는다. 개인 원문·질의·판정은 공개 저장소에 없다.

## 재현과 증거 소유

[Developer Guide](../../policies/project/development/search-comparisons.md#operations)의
`benchmark-search-precision.py`가 기존 RRF, 고정 보너스 후보와 당시 v2 원문-cosine
순위를 재현한다. 현재 hybrid는 v3이므로 이 도구는 dense와 정확 식별자 경로로
v2의 비교 기준을 유지한다. 품질 비교의 질의 벡터 재사용은 속도 측정에 쓰지 않는다. 임시 합성 색인은
자동 제거하고 지정한 private output에 hash·runtime·질문별 정답과 결과를 보존한다.
이 실행의 품질·개인 관측·검증 영수증은 기존 Development owner의
`natural-search/precision-v1/`에 있다. 공개 commit·push·게시를 수행하지 않았다.
