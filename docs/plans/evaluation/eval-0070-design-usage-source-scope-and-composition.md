## Checks And Evidence

- Dynamic Source peers reuse the established segmented-control family; `All` and
  configured names are presented without a nested account selector.
- Personal and company Codex share Codex provenance color/cue, while configured
  labels remain visible in controls, history orientation, composition, and trust.
- Source identity, usage composition, calculation coverage, and synchronization
  health retain separate structural roles and semantic colors.
- Long configured source labels stay inside a horizontally scrollable peer
  control; narrow rules preserve intrinsic option widths rather than shrinking
  distinct labels into ambiguous cells.
- Source composition uses the existing identity/value/evidence grid. Trust rows
  contain latest source result, last success, selected records, and bounded error
  text with explicit wrapping.
- Rendered Jinja evidence confirms Codex Company selection, Codex provider cue,
  readable history label, unavailable result, retained-data consequence, and
  empty-state source ownership.
