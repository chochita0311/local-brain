## Goal

The owner subsequently approved [FEAT-0096 inspection](feat-0096-auto-work-inspection.md)
as a narrow pre-quality UI consumer on `2026-09-16`. This does not change this
Feature's outstanding quality assessment or authorize production replacement.

Establish one reproducible, bounded experiment contract and executable local
prototype that compares reference-only grouping with outcome-level text
extraction. Resolve whether the admitted non-model evidence is sufficient for
automatic work reconstruction before production identity or replacement UI.

The deliverable is an executable comparison with inspectable evidence and an
honest viability result, not another pair normalizer, candidate inbox, or a
claim that a passing test runner proves useful workstreams.

## Acceptance Contract

1. Both arms consume the same frozen source snapshot, with matched eligibility,
   time bounds, and coverage. A metadata arm receives no body text; a text arm
   adds only the PRD's admitted, bounded text. Existing organization is optional
   attributed evidence, never ground truth; also run both arms without it.
2. The text prototype actually extracts evidence-scoped subject, desired change,
   stated completion condition, contribution, and outcome from Korean/English
   requests and decision text. It groups supported compatible outcomes, keeps
   contributing phases subordinate, and separates conflicting outcomes even
   when they share references. Missing meaning stays unknown; no model,
   fixture-specific identity lookup, fixed global group count, or required
   user-supplied assignment supplies the answer.
3. Every extracted field and membership has a source/span locator and observed
   versus inferred attribution. Mixed Sessions can contribute different spans
   to different flows. A source-only working label is not owner confirmation.
   Generic shared words, project identity, or a reference pair cannot alone
   prove one outcome, its completion, or a causal relation.
4. A comparison report distinguishes algorithm quality, evidence sufficiency,
   processing coverage, and harness correctness. It records all inferred flows
   and unassigned scope before any display filtering, plus the PRD's coverage,
   false membership, fragmentation, correction, and stability measures.
5. Unchanged replay is deterministic. Chronological snapshots, unrelated append,
   source loss/rename, and supplied synthetic corrections test continuity.
   Prototype identity/revision and correction replay are experimental state;
   they neither mutate the existing assertion ledger nor settle production
   persistence, automatic scheduling, or permanent flow identity.
6. Private input selection and analysis are explicit, local, bounded, read-only,
   and fail closed. No app initialization, migration, synchronization, model,
   connector, network request, source crawl, or legacy mutation occurs.
7. The implementation cannot claim extraction viability from synthetic checks
   alone or silently replace an inadequate private sample. Failure, missing
   required local evidence, and unresolved assessment remain visible and block
   UI handoff.

## Experiment Inputs And Bounds

These are approved experiment limits, not blanket authorization to inspect
the owner's current database. Exact private paths and record identities are
runtime parameters and must never be placed in tracked artifacts.

| Input or resource | Approved bound and admission |
| --- | --- |
| Primary Sessions | Hard maximum 60, from at most 8 explicitly selected registered source instances; only primary work with full indexing |
| Local trial sufficiency | 40–60 Sessions, at least 10 independently identifiable efforts, and one effort spanning more than 24 Sessions; include weak/no-reference material |
| Related local content | At most 20 enabled/readable Local Context Documents and 20 already-indexed Jira/Wiki Items explicitly present in the manifest; no recursive expansion |
| Existing organization arm | At most 20 supplied goal/checkpoint records and 200 existing relationship facts within the same scope; both arms also run with these removed |
| Reference facts | At most 12,000 existing canonical evidence occurrences; report insufficiency instead of silently retaining only favorable pairs |
| Metadata baseline output | At most 4,096 qualifying pairs across the experiment; deterministic bounded batches respect the unchanged normalizer's per-call limits |
| Text inspection | At most 200 eligible request/decision events per Session, 4,000 Unicode code points per event, 32,000 total per Session; at most 8,000 per Document/Item and 2,000 per organization record; 2.5 million total code points per snapshot |
| Execution | At most 120 seconds wall time and 512 MiB peak process-tree memory per arm/snapshot; record measured usage; no silently unenforced cap |
| Local output | At most 10 MiB per experiment, excluding existing source storage; no full database copy or complete source-body export |

- Required local parameters: existing database path, explicit source/time and
  record scope, snapshot boundaries, and a private output owner outside the
  repository. No current-working-directory or default-live-database discovery.
- The local manifest freezes exact IDs, source permissions, stable ordering,
  selected spans, hashes, analysis/scoring versions, and all caps before scoring.
  Missing or invalid scope fails without creating or initializing a database.
- Manifest preparation may inspect only admitted local metadata and bounded
  indexed text after Feature approval and an explicit local invocation. It
  cannot fetch more records to satisfy the desired number of expected efforts.
- Skip maintenance, provider-internal and Subsession content, raw tool payloads,
  and reference/metadata-only bodies. Existing schema capability is not evidence
  of current content availability or permission.
- Span selection must be deterministic and independent of predicted or expected
  assignments. The frozen sampling/section-selection scope defines the bounded
  trial, not whole-history coverage. Report outside-sample material separately;
  do not shrink that scope after observing scores. Any cap, missing source,
  exclusion, or truncation inside the frozen admitted input makes processing
  coverage incomplete and prevents a complete-evidence pass.
- Private expectations, content, IDs, labels, and detailed reports stay under
  the explicitly selected local owner and never enter the hosted coding agent's
  tool output, prompts, telemetry, or repository. Default command output uses
  fixed status codes; sharing even non-identifying aggregates is explicit.
- Keep only selected evidence spans needed for local review/replay. Task-owned
  scratch is removed when its purpose ends; a retained private comparison
  artifact needs an explicit owner and expiry. No permanent full-copy archive.

## Comparison And Scoring

- Use FEAT-0090's unchanged pair contract as the reference-only comparator,
  not as a producer already present in the application. Construct proposed
  pairs only inside the experiment and combine exact pair identities across
  bounded batches without changing their membership semantics. Report global
  pair-limit overflow, never silently pick favorable pairs or expand the old
  normalizer's per-call contract. Partial baseline coverage prevents a claim
  of a complete matched comparison.
- The text arm uses versioned deterministic rules for explicit intent,
  continuation, contribution, and contradiction. It may normalize language and
  source roles but cannot read expected group IDs, golden labels, or test-case
  names. Unfamiliar/paraphrased goals remain a measured capability question.
- Author synthetic expectations before implementing the extraction rules.
  Include held-out mixed-language and paraphrased cases, renamed subjects,
  shuffled input, changed references, and negative controls from the
  [mandatory scenario matrix](../prd/prd-0017-source-backed-workflow-map-and-workstream-lenses.md#mandatory-scenario-matrix).
  The builder must not weaken expectations to make its own output pass.
- Establish private expected efforts and contribution reasons locally from
  independent source evidence, before showing algorithm outputs. The preparation
  path cannot use either arm's predictions as the answer key. No whole-sample
  naming or Session-assignment task is imposed on the owner.
- At most one local review batch of five consequential ambiguous cases is
  approved for expectation/correction assessment. Unresolved expectations and
  unassessed corrections remain counted as unknown; if they prevent a verdict,
  return insufficient evidence instead of repeatedly requesting more review.
- The PRD's [quality targets](../prd/prd-0017-source-backed-workflow-map-and-workstream-lenses.md#proposed-quality-targets)
  were frozen at Feature approval: zero routine confirmations; all mandatory synthetic
  scenarios; no incompatible-outcome merge or source/legacy violation; at least
  80% goal coverage; at most 10% incorrect membership; at most one excess group
  per ten recovered efforts; at least 90% correction-free recovered efforts;
  deterministic replay and at least 95% stability after unrelated append.
- Report integer numerators/denominators without rounding a failure into a pass:
  expected efforts, recovered efforts, assessed emitted span-to-flow assignments,
  contradictions, assessed recovered efforts needing no correction, and prior
  assignments/identities retained. Zero denominators are not passing scores.
  Evidence may support multiple efforts only through independently justified
  scoped memberships; unrelated Session text cannot improve coverage.
- Establish expected-to-output matching without predicted names as truth. A
  goal is recovered only when its expected outcome and supporting contributions
  are recognizable; raw pair hits or many single-span fragments do not suffice.
  Count excess groups per matched effort, unsupported groups, and unmatched
  expectations separately. Missing efforts cannot count as correction-free;
  unassessed assignments or corrections cannot be silently scored correct.
- Evaluate both arms on identical input, without organization, and across at
  least three chronological snapshots plus unchanged replay, unrelated append,
  renamed/late/removed source evidence, and synthetic exact-scope corrections.
  A metadata arm's poor grouping does not excuse failure of the absolute text
  quality gates. Do not resample or tune against the private answer key.

- Extraction/scoring lane (`src/localbrain/`, synthetic `tests/`): pure supplied
  evidence to experimental work statements, inferred groups, coverage, and
  comparison metrics. Contract owns attribution and scoring; Functional owns
  scenario/replay behavior. It passes before private-input adapter use.
- Local experiment lane (`scripts/`, focused adapters/tests): explicit invocation,
  read-only snapshot admission, bounded private output, resource enforcement,

  failure isolation and absence of hidden operations. No browser lane.
- Report versions and source manifests belong to the experiment, not existing
  Workstream rows, Episode assertions, Suggestions, or production cache owners.
- Likely owner updates during approved implementation: the narrow experimental
  boundary in Product, Architecture, and Privacy documentation; new experimental
  code and focused tests. Do not relax the current Focus or pair-only contracts.

## Entry And Exit

- Entry: approved Feature and Spec, then explicit synthetic comparison. Private
  execution additionally requires the bounded local manifest and successful
  synthetic safety checks; it is not started by import or normal app entry.
- Technical result: implemented comparison/admission/scoring behavior with
  synthetic evidence. This alone is not a product viability pass.
- Viability pass: complete synthetic and scoped local evidence meets every
  adopted gate; report eligibility for a later production-foundation proposal.
- Quality failure: preserve measurements and return the work-unit/extraction
  decision to PRD planning. Do not build an approval inbox or silently invoke a
  model to compensate. A local-model comparison needs separate admission.
- Insufficient/unexecuted: record missing evidence and no UI handoff. An
  unrun local trial, unavailable independent expectations, partial input, or
  cap exhaustion must not become a full PASS or an invented measurement.

## Pass Or Fail Checks

- Golden, held-out, metamorphic, and negative-control cases exercise real
  extraction/grouping, not only normalized pre-labeled candidates.
- No-org and mixed-Session cases work without create/assign/name/accept/promote;
  all source-derived assertions retain their exact evidence and authority.
- Metric edge cases cover empty denominators, unresolved expectations,
  unassessed corrections, overlapping scopes, duplicate evidence, fragmented
  output, false merges, and excessive abstention before any display cap.
- Read-only synthetic database tests prove no DDL/DML or initialization; guard
  model/network/scan entry points and every excluded source/body class.
- Boundary tests exercise each input/output/resource cap, cancellation,
  unavailable inputs, malformed manifests, deterministic replay, and private
  content/ID suppression from default output and tracked reports.
- A working runner with missing or failing local quality evidence must not
  receive complete viability coverage or authorize replacement UI.
